# ART STYLE BIBLE - 초안 v0 (D0 · 2026-09-25)

> **"Roblox에서 한눈에 알아볼 수 있는 밝고 과장된 카툰형 액션 게임."**
> 가장 중요한 기준: 예쁜 에셋 하나가 아니라 **모든 에셋이 같은 게임에서 나온 것처럼 보이는 것**. 목표는 스크린샷 한 장으로 스타일이 기억되는 것이다.

- 원문: `docs/direction/0925-user-direction.md` 4장 · 5장. 현재 상태 근거: `docs/phase/D0-audit.md` 부록 D §7 ~ §11.
- 이 문서는 **초안**이다. 수치(외곽선 두께 · 색 값)는 시범 A1에서 스크린샷으로 확정하고 v1로 올린다.
- 참고 이미지 4장(`docs/art/ref/`, git 제외)은 **복제 대상이 아니다.** 아래 §2의 "문법"만 가져온다.

## 1. 여섯 원칙 (원문 고정)

| # | 원칙 | 이 게임에서의 뜻 |
|---|---|---|
| ① | 어두운 외곽선 = 게임 전체의 공통 언어 | 지형 · 바위 · 나무 · 건물 · 상자 · 무기 · 몬스터 · 보스 · 주요 이펙트 · UI 핵심 아이콘이 같은 외곽선을 공유한다. 목적은 "까만 테두리"가 아니라 **멀리서도 형태가 즉시 구분되는 실루엣** |
| ② | 밝고 채도 높은 색 | 플레이어 · 적 · 환경 사이 대비가 크다. 희귀도는 색 + 효과로 |
| ③ | 과장된 실루엣 | 실제 비율보다 재미를 위해 크게. 작은 화면(폰 800 × 360)에서도 무엇인지 보인다 |
| ④ | 귀엽지만 액션성 | 둥근 형태 + 강한 동작(늘어남 · 찌그러짐 · 멈칫) |
| ⑤ | 표정 · 포즈로 성격 | 보스 · 몬스터는 얼굴과 자세가 먼저 읽힌다 |
| ⑥ | 희귀도 · 성장이 눈에 보인다 | 숫자만 오르는 RPG가 아니라 **눈으로 성장하는 RPG** |

- **가독성이 예쁨보다 먼저다.** 플레이 중 즉시 구분해야 하는 것: 플레이어 · 적 · 보스 · 공격 범위 · 위험 지역 · 드랍 아이템 · 상호작용 오브젝트 · 보상 · 진행 방향 · 중요 장소.
- 이미 정한 규칙과 같은 방향이다: **보이는 장판 = 실제 판정**(아트가 판정 범위를 속이면 안 된다) · **중앙 금지 구역**(화면 중앙 40% × 50%에 2D UI 없음).

## 2. 참고 이미지에서 가져오는 문법 (복제 금지)

| 참고 | 가져오는 것 | 가져오지 않는 것 |
|---|---|---|
| 알 아이콘 목록(희귀 알 4종) | ① 한 가지 기본 형태(알)를 두고 **표면 재질 · 색만 바꿔 등급을 표현** ② 두꺼운 어두운 외곽선 + 한쪽 하이라이트 광택 ③ 반짝이 점 수가 희귀도와 함께 는다 ④ 작은 크기(64px)에서도 형태가 뭉개지지 않는 단순한 실루엣 | 알 형태 · 무늬(얼룩말 · 무지개 · 금) 그대로 쓰기. 이 게임의 등급 아이콘은 **장비 부위 실루엣**을 기본 형태로 쓴다 |
| 게임 페이지 패스(X2 돈 · X2 성장) | ① **효과를 상징하는 사물 1개 + 큰 배수 숫자**(돈다발 + ×2 / 알 + ×2 + 빨리감기 화살표) ② 금색 원판 · 방사형 빛 배경 = "상품" 표시 ③ 굵은 흰 글자 + 검은 외곽선 | 돈다발 · 알 · 금화 원판의 모양 그대로. 숫자 외 글자(번역 안 됨) |
| 대장간 썸네일 | 색감(따뜻한 조명 + 차가운 벽의 대비) · 부드러운 광원 · 불꽃 파티클의 과장 정도 · 검 날의 색 단계(흰 → 주황 → 하늘 → 금 → 보라 → 청록) | **모루 + 검 진열 구도는 절대 따라 하지 않는다**(같은 장르라 가장 닮아 보이기 쉬운 구도). 검 모양 · 벽 걸이 배치 |
| 롤 스킬 툴팁 | **키워드 색 구분 방식만**(피해 = 한 색 · 상태이상 = 다른 색 · 수치 = 굵게) | 정보량. 이 게임은 **짧은 1줄 기본 + 길게 누르면(PC는 Shift 호버) 상세 2단** |

- 한 줄 원칙: "Steal An Egg 등 특정 게임의 스타일을 복제하지 말고, Roblox에서 강하게 보이는 카툰 디자인 원리를 이 게임의 세계관(대장간 · 강화 · 보스 사냥)에 맞게 재해석한다."

## 3. 제작 방식 - 지금 기술로 가능한 것

### 3-1. 모델 제작

| 방식 | 지금 쓰는 곳 | 장점 | 단점 · 한계 |
|---|---|---|---|
| **파트 조립**(Block · Ball · Wedge · Cylinder) | 몬스터 · 보스 전부 · 활 · 아레나 · 사냥터 지형 | 코드로 생성 · 수정(Claude가 직접 만들 수 있다) · 판정 데이터와 한 곳 | 둥근 형태 · 표정이 약하다. 파트 수가 늘면 16인 화면 파트 예산(1,500)을 먹는다 |
| **MeshPart**(외부 모델링 → 업로드) | 검 · 쌍검 · 지팡이(무료 메시) | 실루엣 · 표정 자유. 파트 1개 | 제작 도구가 저장소 밖(블렌더 등). **업로드는 사용자 몫.** 무료 모델은 스크립트 검사(S21) 대상 |
| **생성형 3D**(Studio MCP `generate_mesh` · 힉스필드 3D) | 없음 | 빠른 초안 | 결과 편차가 커서 스타일 통일이 어렵다 → **시범에서 1개만 시험하고 기준 통과 시에만 사용** |
| **SurfaceGui · Decal**(표정 · 문양) | 없음(광장 문양 자리만 예약) | 파트 몸통에 얼굴 표정을 싸게 붙인다 | 이미지 업로드는 사용자 몫 · 이미지 속 글자 금지(번역 안 됨) |

### 3-2. 외곽선 방식 비교

| 방식 | 원리 | 두께 조절 | 비용 | 쓰는 곳(제안) |
|---|---|---|---|---|
| **Highlight** | 엔진 후처리 외곽선 | **조절 불가**(화면 기준 일정한 가는 선) | 화면의 첫 Highlight가 비용 대부분(모바일 GPU 최대 약 1ms) · 모바일은 화면을 많이 덮을수록 비쌈 · **꺼짐 / 완전 투명이면 0** · 인스턴스 추가/삭제는 순간 부하 → 미리 만들고 켜고 끈다. **동시 표시 한도 255**(2025-11-10 공지 · [문서](https://create.roblox.com/docs/effects/highlighting) · [공지](https://devforum.roblox.com/t/lights-camera-more-highlights/4061534)) | 보스 · 중요 장소 · 상호작용 오브젝트(가까울 때만) · 조준 대상(지금처럼) |
| **뒤집힌 헐(inverted hull)** | 본체보다 조금 큰 복제 메시를 안팎을 뒤집어(법선 반전) 어두운 색으로 뒤에 둔다 | 세계 단위 두께(크기별 규칙 가능) | 파트 · 메시 수 ×2(삼각형 ×2). 법선 반전 메시는 **외부 도구에서 만들어 업로드**해야 한다(파트로는 뒤집기 불가) | 큰 지형지물 · 나무 · 바위 · 무기 메시 |
| **껍데기 파트**(본체보다 큰 검은 파트를 뒤에) | 헐의 파트 버전 - 단순 형태(상자 · 원기둥)만 | 세계 단위 | 파트 ×2 · 겹침 깜빡임(z-fighting) 주의 | 단순한 상자 · 울타리 · 발판 모서리 |
| **테두리 파트**(윗면 가장자리에 어두운 얇은 파트) | 윤곽 일부만 그림 | 자유 | 파트 +4 정도 | 플레이 영역 바닥 경계 · 발판 윗면 |

- **거리별 끄기(LOD)**: Highlight는 카메라 거리 60stud 밖이면 끈다(`Enabled = false` → 비용 0). 헐 · 껍데기 파트는 StreamingEnabled 반경(권장 600)에 맡긴다. 보스 · 플레이어 외곽선은 끄지 않는다.
- 지금 한도 판단의 근거였던 "Highlight 31개"(`BossArenaMapData.lua:7-8` 주석)는 낡은 전제다. 한도보다 **모바일 화면 덮는 면적**이 새 제약이다.

### 3-3. 외곽선 두께 규칙 (초안 - 시범에서 확정)

| 대상 크기(가장 긴 변) | 방식 | 두께(세계 단위) | 비고 |
|---|---|---|---|
| < 2stud(작은 소품 · 드랍 아이템) | Highlight 또는 없음 | - | 작은 디테일을 뭉개지 않게. 드랍 아이템은 등급색 빛이 외곽선 역할 |
| 2 ~ 8stud(상자 · 몬스터 · 무기 · 플레이어) | 헐 / 껍데기 | 0.08 ~ 0.12 | 몬스터 · 플레이어는 캐릭터 대비를 위해 같은 두께 |
| 8 ~ 30stud(나무 · 바위 · 건물 · 보스) | 헐 + (보스는 Highlight 추가) | 0.15 ~ 0.25 | 보스는 두 겹 = "게임의 대표 캐릭터" |
| > 30stud(절벽 · 벽 · 지형 경계) | 테두리 파트 | 0.3 ~ 0.5 | 윤곽 전체가 아니라 **플레이 영역과 만나는 윗면 가장자리**만 |

- 외곽선 색: 순검정이 아니라 **본체 색의 아주 어두운 같은 계열**(명도 10 ~ 15%). 지금 아레나 색 `UIColors.metalOuter`를 기준으로 한 표를 데이터에 둔다.

## 4. 팔레트

### 4-1. 역할별 예약 색 (가독성 규칙 - 환경 · 장식에 쓰지 않는다)

| 역할 | 색 계열 | 규칙 |
|---|---|---|
| 위험(보스 장판 · 전조) | 빨강 · 주황 | **환경 · 장식에 쓰지 않는다.** 용암 같은 바닥이 필요하면 채도를 낮춘 갈색 계열로 |
| 희귀도 | §6 등급 색 7가지 | 드랍 · 아이콘 · 무기 발광에만. 환경에 같은 색 금지(특히 유물 금색 · 태초 무지개) |
| 아군 · 자기 | 하늘색 · 흰색 | 치유 · 쉴드 · 아군 표시 |
| 상호작용 · 목적지 | 노랑(조준 노랑 255,230,90과 같은 계열) | 강화대 · 보석상인 · 포탈 · 이정표 |

### 4-2. 플레이 영역 vs 장식

| 층 | 대비 · 채도 | 외곽선 |
|---|---|---|
| 플레이 가능 바닥 | 명도 대비 높음 · 바닥 패턴(타일 · 잔디 결) 명확 | 경계 테두리 파트 |
| 장식(동선 밖) | 채도 −20% · 명도 대비 낮춤 · 플레이어 키보다 높은 것은 바깥쪽에만 | 얇게 또는 없음 |
| 중요 장소(포탈 · 보스방 입구 · 상점 · 보상) | 고유 색 + 빛 + 실루엣(탑 · 아치) | Highlight(가까울 때) |

## 5. 모양 언어

| 대상 | 모양 | 이유 |
|---|---|---|
| 플레이어 · 아군 · NPC | 둥글고 짧은 비율, 큰 머리 | 친근함 · "귀엽지만" |
| 일반 몬스터 | 둥근 몸 + **tier가 오를수록 뿔 · 가시 · 각** | 위험도가 모양으로 오른다(지금은 모든 tier가 "상자 + 공"에 색 · 크기만 다름) |
| 보스 | 몸통 과장(한 부위가 몸의 절반) + 고유 무기/신체 특징 | 실루엣만 보고 어느 보스인지 |
| 위험 표시 | 뾰족 · 톱니 · 화살표 | 바닥 장판 가장자리 = 판정 경계(보이는 장판 = 판정) |
| 상호작용 · 보상 | 네모 + 위로 솟은 표지(깃발 · 빛기둥) | 멀리서 위치가 보인다 |
| 구조물(아레나 기둥 · 단상) | 굵은 원기둥 · 넓은 판 | 뒤에 숨을 수 있어 보인다(성기사 방패와 같은 문법) |

### 6-2. 무기 - 등급마다 외형이 바뀐다 (지금은 직업별 1종 + 강화 이펙트만)

| 등급 | 실루엣 | 재질 · 색 | 장식 | 효과(VFX) |
|---|---|---|---|---|
| 일반 | 기본형(직업 무기의 가장 단순한 모양) | 무광 금속 · 나무 | 없음 | 없음 |
| 희귀 | 기본형 + 날/머리 한 곳 확대 | 파랑 포인트 | 작은 보석 1 | 없음 |
| 영웅 | 형태 변형(날 끝 갈라짐 · 가드 날개) | 보라 포인트 · 광택 | 문양 1 | 약한 빛 |
| 전설 | 실루엣 강화(크기 +15%) | 주황 발광 줄 | 문양 + 보석 2 | 휘두를 때 궤적 |
| 유물 | 고유 실루엣(날 모양 자체가 다름) | 금 | 떠 있는 장식 조각 | 궤적 + 반짝이 |
| 고대 | 고유 실루엣 + 비대칭 | 빨강 발광 | 룬 문양 발광 | 궤적 + 불꽃 입자 |
| 태초 | **멀리서도 알아보는 고유 형태** | 무지개 순환 | 주변을 도는 조각 | 고유 효과 1(직업별) |

- **강화 이펙트(+5 ~ +30)는 등급 외형 위에 겹친다**(지금 `EnhanceVisualData` 그대로). 등급 = 모양, 강화 = 빛. 두 축을 섞지 않는다.
- 직업 4(성기사 추가 시 5) × 7등급 = 28(35)개. 한 직업 7등급을 먼저 만들어 규칙을 굳힌다(시범 A1).

### 6-3. 방어구 - 등급마다 외형 3 ~ 4개

- 지금 방어구는 **캐릭터에 입혀지지 않는다**(땅 드랍 파트 4종 + UI 아이콘뿐). 입히려면 Accessory · 레이어드 의상 또는 파트 부착이 필요하다 - 비용이 커서 로드맵에서 별도 단계.
- 규칙: 등급당 외형 3 ~ 4개. **옵션 범위(굴림 하위 · 중위 · 상위 · 최상위)에 따라 외형이 갈린다**(원문 제안). 능력치는 같은 등급이면 외형과 무관.
- **이름 규칙 - 이름만 보고 등급을 알 수 있게**: `[등급 접두어] + [외형 이름]`. 접두어는 등급마다 하나로 고정(예: 일반 "낡은" · 희귀 "단단한" · 영웅 "영웅의" · 전설 "전설의" · 유물 "유물" · 고대 "고대" · 태초 "태초의" - 확정은 번역 용어집과 함께). 외형 이름(예: "철판 갑옷" · "비늘 갑옷")은 자유. 이름 글자색 = 등급색.

## 7. 보스 행동 세트

| 행동 | 필수 | 지금 구현 | 제작 방식 |
|---|---|---|---|
| 대기(Idle) | 숨쉬기 · 좌우 흔들림 · 보스별 버릇 1개 | **없음** | 클라 복제 인형(`BossMotionView`) 절차적 - Animation 없이 |
| 등장 | 떨어지기/솟기 + 포효 + 화면 흔들림 | 없음(입장 유예 2초만) | 유예 2초 안에 끝나게 |
| 공격 준비 | 전조와 같은 길이 · 몸이 먼저 말함 | ring 3종 · charge 2종만(P3d) | 전조 시간은 판정 데이터를 그대로 읽는다 |
| 일반 공격 | **보스마다 2 ~ 3종, 같은 모션 반복 금지** | 평타 1종 · 모션 없음 | 평타에 짧은 휘두르기 모션(0.2 ~ 0.3초) - 판정 시각 불변 |
| 강공격 | 크게 들기 → 멈칫 → 찍기(P3d 비율 60 · 25 · 15%) | ring · charge만 | 같은 비율을 다른 스킬로 확장 |
| 특수(기믹) | 보스 고유 포즈 | 없음 | 서리 거인 · 수정 여왕부터(몸 모션 0) |
| 피격 | 흰 번쩍 + 작은 움찔(몸 기울기 5°) | 흰 번쩍만 | |
| 분노(HP 20%) | 색 변화 + 김/불꽃 + 속도 표현 | 전역 쿨 2.5초만(표시 없음) | |
| 사망 | 휘청 → 쓰러짐 → 터짐(보상 연출과 연결) | 줄며 사라짐(0.35초) | 1.5초 안 |

- 보스는 **회전해야 한다**(지금은 회전 없이 평행 이동 - `MonsterAI.server.lua:194`). 얼굴이 플레이어를 보는 것이 표정 · 포즈 문법의 전제다. 판정에는 영향 없음(판정은 중심 거리).
- 몬스터(잡몹)도 최소 세트: 대기 흔들림 · 이동 통통 튀기 · 평타 몸 내밀기 · 피격 · 사망.

## 8. VFX 규칙

1. **짧게**: 타격 0.15 ~ 0.4초 · 스킬 본체 ≤ 1.2초 · 궁극기만 예외(≤ 3초).
2. **전조를 가리지 않는다**: 위험 장판 · 전조는 항상 VFX 위 층. 아군 VFX는 보스 전조 범위 안에서 불투명도 50% 이하.
3. **방향성**: 공격 VFX는 시작점 → 끝점 방향이 보인다(속도선 · 쐐기).
4. **대표 서명**: 모든 주요 공격에 알아볼 수 있는 모양 하나(색 + 모양). 같은 말풍선 그림 공유(지금 `bubble` 4종 공유)는 보스별로 나눈다.
5. **다른 사람 효과는 줄인다**: 지금 규칙(다른 멤버 효과 ×0.5 · 동시 조각 상한 90 · 풀 120 - `BossFxData.lua:20-24`)을 전 VFX 공통으로.
6. 화면 흔들림은 설정에서 끌 수 있게(지금 Attribute로 끔 - 설정창은 P4).

## 9. 2D 아이콘

- 제작 한계: Claude는 **SVG를 만들고 로컬에서 PNG로 렌더**할 수 있다. **업로드(에셋 id 발급)는 사용자 몫**이다. 한 번에 한 세트(예: 등급 아이콘 7장)씩 만들어 확인받는다.
- 규칙: 64px에서 읽힌다 · 두꺼운 어두운 외곽선(64px 기준 3 ~ 4px) · 한쪽 광택 · 등급은 테두리 · 배경 원판 색 · **글자 없음**(숫자 배수 "×2"만 예외 - 숫자는 번역이 필요 없다).
- 장비 아이콘은 지금 Frame 조합(`client/ItemIcons.lua`)이다. 이미지로 바꿀 때 한 곳(아이콘 모듈)만 고치도록 유지한다(CLAUDE.md "그리기는 한 곳에만"과 같은 원칙).

## 10. 패스 · 상품 아이콘 · 수익화 원칙

- **아이콘 문법**: 효과를 상징하는 사물 1개 + 큰 배수(×2) + 상품 원판(금 테두리 · 방사형 빛). 예(이 게임의 사물로): 골드 ×2 = 금화 자루 · 경험치 ×2 = 위로 솟는 화살표 달린 별 · 강화 편의 = 망치 + 반짝이 · 가방 칸 = 열린 가방. **다른 게임의 돈다발 · 알 · 원판 모양을 그대로 쓰지 않는다.**
- 수익화 원칙(구현 때마다 확인):
  1. 돈을 쓰면 **더 편하게 · 더 빠르게 · 더 화려하게**. 기본 게임의 재미를 대체하지 않는다.
  2. **기본 게임을 불쾌하게 만들어 파는 구조 금지**(일부러 불편하게 두고 패스로 푸는 것 금지).
  3. 리더보드 공정성: 순위에 직접 들어가는 힘(공격력 배수 등)은 팔지 않는다 - 순위는 "보스 클리어 기준 · 이론 최소 시간"이 지킨다.
  4. 확률형 상품은 확률을 보여준다(드랍표 조회 API가 이미 있다).
