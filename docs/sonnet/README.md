# Sonnet 세션 로드맵 (30-0에서 작성)

설계 · 결정의 근거는 전부 `PRD-forge-game-roblox.md` **20.81**에 있다. 이 폴더는 그 결정을 Sonnet이 **판단 없이** 순서대로 실행하기 위한 세션 프롬프트다.

## 쓰는 법

1. 아래 표에서 **완료 표시가 없는 가장 앞 번호**를 고른다(의존성 칸의 세션이 전부 `[x]`인지 확인).
2. 새 Sonnet 세션을 열고 그 파일(`Sxx-….md`)의 내용을 통째로 프롬프트로 준다. 파일 하나 = 세션 하나.
3. 세션이 끝나면 Sonnet이 이 표의 완료 칸을 채운다. **미결 칸에 글이 남은 세션은 Fable로 가져온다.**
4. ◆ 줄에 닿으면 Sonnet 구간을 멈추고 Fable 세션을 연다.

- 공통 규칙(`COMMON.md`)은 모든 세션 파일 끝에 들어 있다. 공통 규칙을 고칠 때: `COMMON.md` 수정 → `python docs/sonnet/_build.py` → 세션 파일 전부 갱신.
- 규모: **소** = 파일 2 ~ 4개 · Play 1회 / **중** = 5 ~ 9개 · Play 1 ~ 2회 / **대** = 10개 이상 또는 UI + 서버 · Play 2 ~ 3회. "대"가 한 세션에 안 끝나면 그 파일의 "쪼개는 선"에서 끊는다.

### 검증 원칙: 회귀 전체는 마일스톤에서만

- **모든 Play는 현재 세션 블록만 돌린다**(`DevToolsConfig.verify.regression = false`). 세션 마지막에 회귀 전체 Play를 따로 돌리지 않는다.
- 대신 그 세션이 **고친 모듈을 쓰는 옛 검증 블록은 함께** 돌린다(예: 강화 코드를 고쳤으면 S03 강화 블록도). 어떤 블록을 같이 돌렸는지는 세션 보고서에 적는다(COMMON.md §3 "동반 실행").
- 회귀 전체(`regression = true`, 약 4분)는 🔁 표시 줄(**S10 · S15 · S21 종료 시**) · **Fable 세션으로 넘어가기 전** · **퍼블리시 전**에만 켠다.

한 번에 한 세션만 돌린다(같은 파일 - `DevTools.server.lua` · `CombatResolution.lua` · `PlayerProfile.lua` - 을 여러 세션이 고친다).
