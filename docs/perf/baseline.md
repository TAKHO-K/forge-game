# 성능 기준선 (P2.5a B - 변경 전, 커밋 `1fc3d6e`의 PerfProbe)

측정 도구 = `roblox/src/server/PerfProbe.lua`(개발 전용, `/gg perf` 또는 edit 모드 Attribute `PerfAutoRunUntil`) + 클라 수집기(클라 `execute_luau` - RenderStepped · DescendantAdded · OnClientEvent를 장면 Attribute `PerfScene`별로 모음). 2026-09-23 Studio(0.740) 솔로 Play, 개발 계정(레벨 1 · 스테이지 1로 강제 · 측정 중 HP 유지). 게임 판정 경로를 그대로 쓴다: 사냥 부하 = 가장 가까운 잡몹에 직업 평타 쿨다운(도적 0.28 ÷ 공속)마다 `MonsterState.applyDamage` → `AttackResult:FireClient` → `CombatResolution.resolveHit`(1마리 6타).

**읽는 법 · 한계**
- Studio는 60 fps 상한이라 프레임 간격 평균은 모든 장면에서 16.67 ms다 - 차이는 **서버 Heartbeat 처리 시간**(`Stats.HeartbeatTimeMs`)과 클라 **렌더 CPU/GPU 시간**, p95 · 최대에서 본다.
- 메모리(`GetTotalMemoryUsageMb`)는 Studio 프로세스 전체(편집기 + 서버 + 클라가 한 프로세스)라 3.6 ~ 3.9 GB로 나온다 - 절대값이 아니라 장면 간 증감만 본다.
- "폰" = Studio 창을 줄여 뷰포트 842 × 592 + `ForceTouchLayout`(터치 배치). Device Emulator의 800 × 360 사용자 기기는 MCP로 못 만든다(COMMON §2) - 렌더 해상도 · UI 배치 차이만 반영되고 **기기 성능(실제 폰 CPU/GPU)은 반영되지 않는다.** 실기 측정은 "사람이 확인할 것".
- 원격 호출 "서버 수신"은 0이다 - 측정 중 실제 클라 입력이 없다(부하는 서버가 만든다). 실제 플레이 입력은 평타 1회 = `AttackRequest` 1회(초당 1 / 쿨다운 ≈ 3.6회 - 도적 기준)로 추정.

## B2. 스테이지 전환 1회 비용

| 전환 | 서버 처리 시간 | 생성 · 파괴 인스턴스 | 방식 |
|---|---|---|---|
| 일반(잡몹) 스테이지 → 일반 스테이지 | **0.002 ~ 0.005 ms** | **0**(20회 평균, 1회는 +1 - 드랍 표시가 우연히 겹침) | 인스턴스 재사용 이미 됨 - 잡몹은 구역 격자에 상시 있고 수치는 공격자 스테이지로 매번 계산(`MonsterState.applyDamage`의 `attackerStage`). 전환 = `PlayerProfile.setInfiniteStage`(값 두 개 + Attribute)뿐 |
| 보스 스테이지 진입(보스 스폰) | 1.7 ~ 2.5 ms | +25(보스 모델 10 + 아레나 장치 · 이름표 등) | 매번 생성 |
| 보스 스테이지 퇴장(보스 파괴) | 0.8 ~ 1.0 ms | −19(1초 뒤 - 사망 연출 지연 파괴) | 매번 파괴 |

**결론(풀링)**: 2%에서 잦아지는 것은 "일반 스테이지 전환"인데 그 비용은 이미 0에 가깝다(생성 · 파괴 0). 보스 스폰은 5스테이지마다 그대로(보스 간격 `BossData.stageInterval` 불변)이고 1회 2 ms · 25개라 풀링 이득이 측정 오차 수준 → **풀링으로 바꾸지 않았다**(바꿀 대상이 없다). 처치마다의 잡몹 재생성(모델 11개 인스턴스 파괴 → 5초 뒤 새로 생성)은 스테이지와 무관한 비용이라 이 단계 범위 밖(예산 표에 기록).
