## 2-2. 캐주얼 계승 직후 잉여(ADD 결정 2) → 판정 기준 "보유 시간"으로 · **값 보류**

- 보유 시간 = 계승 ~ +3,000 구간에서 (보유 골드 ÷ 시간당 수입)의 시간 가중 평균(ADD 보고의 "보유" 열과 같은 식).
- 2-1 적용(2.2) 뒤 재측정: 캐주얼 **20.9h**(잉여 12.1% - 기록만) · 일반 11.3h · 상위 1% 4.9h · P90 4.8h → 캐주얼 6h 초과.
- 원인(실제 궤적 `holds.py`): 계승 + 1,000 이후 캐주얼은 초월 +1 칸(43,000마리분 ≈ 28시간치 수입)을 사려고 모으는 동안 골드가 쌓인다(구간별 보유 0.2 → 0.7 → 18 → 28 → 26 → 27h). 즉 **보유 시간 ≈ 칸 가격 ÷ 수입** - 비용을 올리면 늘고 내리면 준다.
- 격자(`transcendEnhance.sureCostFactor` - +1 ~ +5 칸 가격 배수 · 확률 단계 무관 · breakRatio 2.2 위):

- 지시는 "단계 비용을 격자로 올려 ≤ 6h"였지만 올리면 보유가 늘었다(1.5 = 32h). 내리면 0.25에서 6h 안이 되지만 +1 ~ +5가 싸지는 만큼 모든 프로필이 빨라져 "다른 프로필 시간 ±2%"와 "상위 1% 25,300 ≥ 2,150h"(2-1 조건)를 깬다. **두 조건을 함께 만족하는 값이 격자 안에 없다 → 값을 바꾸지 않고 보류**(`sureCostFactor = 1` 자리만 데이터에 추가 · 동작 변화 0).
- 후보(사용자 결정): (a) `sureCostFactor 0.25` + 확률 단계 비용(levelKills)을 올려 25,300 시각을 되돌리는 재맞춤(상위 1% 2,150 ~ 2,400 다시 맞춤 · 실행 약 30분) (b) 캐주얼 보유 20.9h 수용(ADD 원 기준 24 ~ 48h 안) (c) 결정 7 순서 안내에서 캐주얼에게 고급 수련 51 ~ 60(×0.4로 쌈)을 먼저 보여 주기(안내만 · 경제 값 그대로). 추천 (b) - 보유는 "다음 칸을 위해 모으는 중"이라 쓸 곳이 없어 쌓이는 잉여와 다르다.
