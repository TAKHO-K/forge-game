# PROG-2 성장 · 보상 · 펫 개편 설계안 (PROG-2A · 10-11)

> 설계 + 시뮬만. 게임 데이터 · 서버 코드 · 저장 필드는 바꾸지 않았다(4절 끝 "변경 0 확인" 참고).
> 시뮬 = 실제 `EconSim.runProgress` · 실제 `BossDifficultySim`을 로컬 luau 하네스로 돌리고, 바꿀 값은 **하네스 메모리 안에서만** 덮었다(`docs/phase/PROG-2A/sim/`).
> 표기: **T = 비용 ÷ G(s)** = "그 단계 정상 플레이 몇 분어치". 이 문서의 T는 일반 프로필 기준이다. 1마리분 = tier1 잡몹 골드 × 1.001^(s−1)이고, 일반 유저는 분당 약 45 ~ 130마리분(U)을 번다. 그래서 **1마리분 ≈ 1초**다.

## 2. 설계안 (★ = 설계 담당 추천)

### 2-1 능력치 수련 (1회 +1% · 최소 +0.5% · 100회 = +100%)
| | **A안 ★ (통합)** | B안 (공용 100) |

| 25,300 상위 1%(보정 없음) | 2,080h(−3.4% · 하한 밖) | 1,929h(−10.5%) |

| 위험 | 고급 수련 51 ~ 60 할인(× 0.4) 때문에 **50 → 51 계단이 안 보임**(T 14.2 → 9.4분) → 결정 D3 | 고급 수련 · 초월 기준 빌드(All10.referenceBuild)를 다시 맞춰야 함 |

- 가격은 단계 골드를 `GoldCost.niceReward`로 반올림한다(앞 두 자리).
- 예: 스테이지 1,000에서 50단계 = 14,000골드, 스테이지 7,500에서 26단계 = 3,600,000골드(전체 표 = `sim/costtable.py` 출력).
- ★ **몹 HP 보정이 필수**다. +45%(A) · +95%(B)의 영구 배수를 보정 없이 넣으면 상위 1%가 하한 아래로 간다. 보정 = 중앙값(일반 프로필)이 그 스테이지에 실제로 가진 새 힘만큼 몹 HP를 곱한다(ALL10 돌파 계수와 같은 고정점 방식).
- 첫 보정(상한까지 다 산다고 가정)은 1,000 ~ 5,000 구간을 33% 느리게 만들었다. 모형 중앙값은 무기 +30을 마칠 때(스테이지 약 7,000)까지 수련을 사지 않는다. 이 실제 궤적으로 맞춘 것이 fullFP다.
- 한계: 모형은 "강화 비용을 먼저 남김" 규칙이라 신규 30일 동안 수련 0단계로 나온다. 실제 화면에서 수련을 먼저 고르는 사람은 모형보다 빠르다(보정은 중앙값 기준이라 그만큼 이득).

### 2-2 개별 스킬 강화 = 없앰
- **지금 그런 시스템이 없다**(1-2). 그래서 처리안 = "만들지 않음"으로 끝난다.
  - 스킬 수치 = 지금 기본값 그대로.
  - 저장 필드 · 환급 · 이관 없음.
  - EconSim 골드 소모처 변화 0.
- 지시서의 "UI-1b 스킬 묶음 구매 화면 정리"는 실제로는 **수련 · 직업 능력 묶음**(UI-1b 17)을 말한다. 옛 직업 능력 3종 × 50단계가 새 Lv1 ~ 3으로 바뀌므로, 묶음 화면에서 직업 능력 줄을 빼고 2-3 화면으로 옮긴다(PROG-2B).
- 직업 간 격차(전 = 후 · 스킬 강화가 없으므로 같은 값). 직업 능력(2-3) 반영 뒤 값은 아래와 같다.

|---|---|---|---|---|
| 검사 | 0.778 | 1.044(검사 딜러 · 치유사 1) | 포효 받는 피해 −25% | +12% |

### 2-7 환생 무료권
- 효과 = **언제든 즉시 환생**(다음 환생 필요 레벨 무시). 최대 5회 규칙 · 제단 위치 · 보스전/강화 중 금지는 그대로다.
- 사용 흐름(확인 2단계):
  1. 1단계 창
     - 초기화되는 것: 레벨 → 1, 현재 스테이지 → 1
     - 남는 것: 장비 · 강화 · 보석 · 골드 · 수련 · 최고 기록
     - 얻는 것: 무기 등급 +1 · 보석 홈 i번 + 보석 · 이동 해금
     - 팁(압박 문구 금지 · 정보만): "환생 보석은 환생 순간 레벨이 높을수록 좋아요. 지금 레벨 n → 보석 itemLevel n + 167."
  2. 2단계 = "환생권 1장을 써서 지금 환생할까요?" [사용] [취소]
- 팁 문구 시안: "5회차 이후"는 환생이 5회가 끝이라 맞지 않는다 → **"레벨이 높을 때 쓸수록 환생 보석이 좋아요"** ★.
- 플레이 시간 단축은 허용(사용자 결정). 한 장이 건너뛰는 양 = 환생 한 구간의 사냥이다. 기준선 일반 유저의 구간 시간은 환생 1 → 2 = 1.8h · 2 → 3 = 1.4h · 4 → 5 = 3.0h였다(EconSim 실측). 환생권 자체는 시뮬에 넣지 않았다.

|---|---|---|
| 일반 | 10 | 그 단계 1레벨의 1/60 |

| 전설 | 2,400 | 4레벨 |

**승급 합성**: 같은 종 · 같은 등급 3마리 → 상승 9% · 대성공 1%(상승 + 1마리 더: 결과 등급 75% / 한 등급 위 25%). 매번 독립 시행, 불씨 없음, 확률은 화면 공개. 골드 비용 = 대상 등급 T분(희귀 5 · 영웅 15 · 전설 40분 ≈ 300 · 900 · 2,400마리분).

- 내부 안전 상한 = **2^50(1.13e15)** ★. 지금 곡선이면 상위 1%가 852h(s21,580)에 닿는다.
  - 감쇠 곡선 ★과 같이 쓰면 진행 끝까지 안 닿는다(최대 2.8e16 = s29,740 이후).
  - 곡선을 안 바꾸면 상한 2^52 · 표시 압축만으로는 s22,500 이후를 막지 못한다 → 감쇠 곡선 채택 = 결정 D11.
- 공통 검증 함수 `GoldGuard.apply(profile, delta, reason)`:
  - NaN · inf · 음수 거부
  - 결과 > 상한이면 상한에서 자르고 감사 로그
  - 모든 지급 · 지출이 거침(지금 changeGold · trySpendGold 한 곳 → 이 함수를 부르게)
- 표시 = 1.2M 등 화면만 압축(저장 값은 그대로).
- 저장 이관 규칙 문서: 곡선을 바꾸면 기존 보유 골드 × M_new(최고)/M_old(최고)로 환산한다(출시 전이라 개발 계정만).
