# GOLD-CURVE-1 골드 = "땀 화폐" 곡선 설계 (10-11 · 시뮬 · 문서만)

> 게임 데이터 · 코드 변경 0. 시뮬 = 실제 `EconSim.runProgress`를 로컬 하네스로 돌리고 바꿀 값은 메모리 안에서만 덮었다(`docs/phase/PROG-2A/sim/p2lib.lua` · 시나리오 `sim/scen/gc/*.lua` · 앵커 `sim/anchors.py`).
> 프로필 = 캐주얼(1h/일) · 일반 = 중앙값(3h/일) · 상위 1%(12h/일) · 운 나쁜 P90.
> 단위: **1마리분** = tier1 잡몹 골드(4.95) × M(s). 중앙값 유저는 분당 약 45 ~ 130마리분을 번다.

## 요약
- **추천 = C(1,000까지 지금 그대로 · 뒤 √ 완만) + 초월 강화 한 단계 비용 × 1.16.**
  - 상위 1% 2,183.6h(하한 2,150 · 여유 0.2% → 1.6%)
  - 일반 +1.6% · 캐주얼 −2.9% · P90 +0.5%
  - 보유 골드 최대 약 90억(2^50 · 2^53 영원히 안 닿음)
  - 스테이지 8,500에서 25만 골드 = 일반 122분 · 상위 49분(지금 0.2 · 0.1분)
- **곡선은 진행 속도를 거의 안 바꾼다.** 비용(GoldCost)과 수입이 같은 함수 M(s)를 쓰기 때문이다. "강화 한 번 = 사냥 몇 분"은 A와 C가 같다. 바뀌는 것은 **숫자 크기**와 **고정 숫자 보상의 가치**다.
- 곡선을 바꿀 때 따라 고칠 하드코딩 표는 **1개(BossFirstClearGoldData)**, 고정 숫자는 **3곳**(시즌 패스 골드 · 반복 보너스 · 견습 500)이다. 나머지 출처 12 · 소모처 12는 GoldCost/getGoldReward 한 함수를 거쳐 자동으로 따라온다.

## 2. 앵커 표 (분당 골드 G · 10만 골드 = 몇 분 · 25만 = 몇 분 · 그 스테이지까지 보유 골드 최대)
- **A** 지금: M = 1.001^(s−1)
- **B** 구간 감쇠(PROG-2A D11): 성장률 × 1 → 0.6(10,000) → 0.4(17,000) → 0.3(25,300) 직선
- **C** 강한 완만(사용자 앵커): s ≤ 1,000 = 지금 식 · s > 1,000 = M(1,000) × √(s/1,000)
  - M(8,500) = 2.71 × 2.92 = 7.9 · M(25,300) = 13.6
  - 근거: 사용자 앵커 "1,000에서 10만 ≈ 1.7h 그대로 · 8,500에서 25만 = 60 ~ 120분" → 1,000 → 8,500 수입 2 ~ 4배 → 거듭제곱 p = ln 3 / ln 8.5 ≈ 0.51 → **p = 0.5(√)**로 반올림(설명하기 쉬움).
  - 로그형은 1,000 이전부터 휘어 초반 체감이 바뀌고(PROG-2A −28% @1,000), 구간 선형은 꺾임이 여러 개라 버렸다.

## 3. C를 쓰면 같이 바뀌는 것

### 3-1 같은 변환으로 자동으로 따라오는 것 / 손으로 고칠 것
- **자동**: 출처 12 · 소모처 12 = 전부 `InfiniteStage.getGoldMultiplier` 한 함수(GoldCost.scale · getGoldReward)를 거친다 → 함수 하나 교체로 끝.
- **손으로**: 1-4 목록(하드코딩 표 1 · 고정 숫자 3).
- **하한 맞춤 1개**: 초월 강화 levelKills 43만 × 1.16(= 49.88만). 이유는 3-2.

### 3-2 왜 완만한 곡선은 상위 1%를 빠르게 하나 (단독 실험으로 확인)
- 비용은 **계정 최고 스테이지**, 수입은 **사냥 스테이지**(약 50칸 아래)의 M을 쓴다. 지금 곡선에서는 이 차이가 1.001^50 ≈ 5% 비용 할증이다. 곡선이 평평하면 할증이 사라진다.
- 실험: A 곡선 그대로 비용 기준만 50칸 내림 → 상위 1% **2,154.5 → 2,060.5h(−4.4%)**. 가설과 같은 크기다.
- C는 −8.4%(1,973.8h)다. 이 할증을 지금처럼 되돌리는 보정(1.001^50 ÷ (M(s)/M(s−50)))을 넣어도 −5%(2,046h)가 남는다. 남는 몫의 원인은 이번에 확정하지 못했다.
- 그래서 단순한 손잡이 하나로 맞췄다:

|---|---|---|

| C + 할증 보정 + × 1.08 | 2,150.6h | 2,053h |

| **C + × 1.16 ★** | **2,183.6h** | 2,065h |

- C에서 +20이 조금 싼 것은 3-2의 할증 차이(× 1.16은 초월에만 넣음)로 추정한다(단독 확인 안 함).

## 4. 덩어리 보상 규칙 시안 ("그 시점 사냥 n분분" · 유효 숫자 2자리)
- 규칙: **골드 = niceReward(n × 60마리분 × 4.95 × M(계정 최고 s))**. 중앙값 1마리분 ≈ 1초라 60n마리분 ≈ n분이다.
- `GoldCost.niceReward`는 이미 "1,000 미만 100 단위 · 1만 이상 앞 두 자리"다. 지금 마리분으로 정의된 것(출석 · 퀘스트 · 도감)은 **이미 이 규칙**이다(n만 표기).

| 덩어리 | 지금 | 제안 n분(마리분) | 비고 |
|---|---|---|---|
| 시즌 패스 무료 골드 칸 | 3,500 ~ 11,200 고정 | 10 ~ 30분(600 ~ 1,800) | 칸 번호 따라 직선 |
| 시즌 패스 보호 칸(25 · 35) | 3,000 · 4,000 고정 | 10 · 15분(600 · 900) | |
| 시즌 패스 반복 보너스 | 3,600 × 20 고정 | 10분(600) | |
| 견습 완료 | 500 고정 | 그대로(약 2분 · 스테이지 20 고정) | |
| 출석 7일(지금) | 200 · 300 · 500마리분 | 3 · 5 · 8분(그대로) | |
| 신규 7일(PROG-2) | 1,000 · 2,000마리분 | 17 · 33분 | |
| 나무 정상 α(PROG-2) | 30마리분 | 0.5분 | |
| 도감 상자 | 약 444마리분 | 7분(그대로) | |
| 보스 첫 클리어 골드 | 숫자표 | **표 → 함수**: 보스 단계별 n = 지금 표 값 ÷ (4.95 × 1.001^(s−1)) 그대로(곡선만 바꿔 다시 굽기) | |
| **직업 능력 Lv2** | (PROG-2) 10만 | **120분**(7,200마리분) · 개방 시점 기준 | C에서 s1,000 ≈ 10만 그대로 |
| **직업 능력 Lv3** | (PROG-2) 25만 | **270분**(16,200마리분) · 초월 개방 시점 기준 | C에서 s8,500 ≈ 16,200 × 4.95 × 7.9 = 63만 |

- 한 번 사는 것(직업 능력)은 "개방 시점 기준"이 원칙이다. C에서는 숫자가 완만해 실제 가격이 거의 고정처럼 보인다(Lv3: s8,500 63만 · s15,000 84만 · s25,300 109만).

## 5. 골드 배율 정리 시안
- 지금 처치 한 번에 실제로 **겹치는** 보너스는 균열(+25%)과 반짝이(+50% + 125마리분) 두 가지뿐이다. 접두사 · 보스 · tier는 "몹이 단단한 만큼"(HP 비례)이라 보너스가 아니다 → 그대로 곱.
- 시안: **보너스형 배율은 합 · 전체 상한 +100%**(지금 최대 +75%라 상한은 미래 펫 · 패스 · 이벤트 대비).
  - 반짝이 처치 = g × (1 + 0.5 + 0.25) + 125마리분(지금 (0.5g + 125마리분) × 1.25).
- EconSim 영향: 평균 수입 × (1 + 0.1245 + 0.075) / (1.1245 × 1.075) = **× 0.9923** → 상위 1% 2,154.5 → **2,183.6h(+1.3%)**. 하한에 도움이 된다.
- 추천 = 채택(규칙 한 줄 · 미래 배율 폭주 방지).

## 7. 추천 · PROG-2B 작업

**추천 곡선 = C(√ 완만) + 초월 levelKills × 1.16 + 배율 합 규칙**
- 이유 ① 사용자 앵커 그대로: 1,000에서 10만 = 118분(중앙값 · 지금과 같음) · 8,500에서 25만 = 122분(중앙값) / 49분(상위).
- 이유 ② 진행 속도 유지: 4프로필 −2.9 ~ +1.6%. 하한 여유 0.2% → 1.6%(배율 합까지 넣으면 더 늘어남 - 같이 넣은 시뮬은 PROG-2B 고정점에서).

- 이유 ④ 고칠 곳이 적다(함수 1 + 표 1 + 고정 숫자 3 + 값 1).
