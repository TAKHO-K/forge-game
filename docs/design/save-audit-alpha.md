## 2. 손상 입력
| 입력 | 결과 |
|---|---|
| 골드 문자열 · 가방 nil · 칸 수 문자열 · 모르는 옵션 id | 스키마 거부(로드 실패 → 아래 3의 보호) |
| 모르는 필드 · 가방 5,000개 · 음수 골드 | 에러 없이 통과(거부 아님) - **낮음**: 음수 골드는 게임 경로로 못 생기지만 손상 저장이면 그대로 읽힌다 → 로드 때 0 하한 추천 |
| 저장 직전 NaN · inf | 이전 저장 값으로(없으면 0) - 저장 전체가 실패하지 않음 |

## 3. DataStore 흐름
| 항목 | 현재 | 판정 |
|---|---|---|
| 쓰기 | `UpdateAsync`(SaveSystem.saveProfile) | O |
| 재시도 · 백오프 | 3회 재시도 1 · 3 · 6초(SaveConfig) · 읽기도 같음 | O |
| 동시 접속(세션 잠금) | 잠금 없음 · **낙관적 검사**(저장된 savedAt이 내가 읽은 값보다 새것이면 쓰기 취소 → stale_session → 그 세션 저장 중단 + 안내) | △ 덮어쓰기는 막힘 · 늦게 들어온 세션의 진행은 저장 안 됨(데이터 손실 X · 진행 손실 O) - **중요**: 로드 때 old.savedAt이 30초 안이면 잠깐 기다렸다 다시 읽는 "약한 잠금" 추천 |
| BindToClose | 남은 사람 전부 `ImmediateSave.flush` | O |
| 불러오기 실패 | 기본 프로필로 놀게 하되 `SaveCoordinator.notify` = 저장 중단 + 안내 · 게다가 기본 프로필 savedAt 0 → 저장돼도 옛 데이터(savedAt > 0)를 못 덮음(이중 보호) | O |
| 미래 버전(롤백 서버) | `future_version` → 위와 같이 저장 중단 | O |
| 요청 예산 | 자동 60초 + 즉시 저장 6초 스로틀(1인 분당 최대 10) - 100명 분당 약 1,000 < 한도 1,060 | O(여유 작음 - 설정 · 펫 즉시 저장이 늘어 스로틀 공유 확인됨) |

## 4. 복사(dupe) 경로
| 경로 | 하네스 | 결과 |
|---|---|---|
| 판매 연타(같은 칸 두 번) | O | 복사 없음 · **중요**: 두 번째 요청은 밀려 올라온 **다른 장비를 판다**(칸 번호만 보냄 - 부화 Q11 리뷰와 같은 종류). 수정안 = 요청에 장비 서명(등급 · 부위 · 레벨) 대조 또는 판매 요청 0.3초 스로틀 → R3에서 스로틀로 처리 |
| 잠금 장비 판매 · 분해 | O | 거부 |
| 일괄 분해 연타 | O | 두 번째 0 · 보석 = 대상 수 |
| 부화 연타 · 받기 연타 | O | 두 번째 거부(알 번호 + 획득 시각 대조) |
| 출석 · 접속 보상 연타 | O | 두 번째 claimed |
| 튕김 직전 수령 → 재접속 | O(구조) | 받은 표시와 보상이 같은 프로필 한 저장 단위 - 저장 전 튕김 = 둘 다 없음 |
| 자동 줍기 | 코드 확인 | 주인 한 명(ownerId) · 줍기 · 칸 확인 · 바닥 제거가 `tryPickup` 한 곳(Heartbeat 한 스레드) - 복사 경로 없음 |
| 계승 · 각성 | 코드 확인 | 재료 제거 · 결과 반영이 한 함수(동기) · 즉시 저장 - 연타는 재료가 없어져 거부 |
