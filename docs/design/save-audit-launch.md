## 7. 결정 필요

1. **데이터 id 삭제 규칙(출시 뒤)**: 옵션 · 재료 id를 데이터에서 지우거나 이름을 바꾸면 그 id를 가진 모든 계정이 `invalid_schema`로 로드 실패(저장 중단)한다. 추천: "출시 뒤 id 삭제 금지 · 바꿀 땐 SAVE_VERSION 이관으로 옮김"을 규칙으로 + 그래도 남은 모르는 옵션은 `repairProfile`에서 옵션만 비울지(그 장비 옵션 손실) 결정. (보스 id는 표시 전용 도장이라 이번에 자동으로 뺀다 · 새 직업 추가는 자동 기본 상태.)
2. **합동 목표 하루 상한을 프로필로(v62)**: 지금은 MemoryStore 키(사람 · 날짜). 프로필에 `communityGoal.day` · `dayCount`를 두면 MemoryStore 메모리 0 · 서버를 옮겨도 정확(프로필이 따라감). 필드 추가(파괴적 아님)지만 구조 변경이라 결정.
3. **태초 원장 확인 매 접속 다시 읽음**: 태초를 많이 가진 사람일수록 접속마다 GetAsync가 는다(최악 72/분). 확인 끝난 각인에 표시를 남기면 0 - 각인 필드 추가라 결정.
4. **1인 서버 GetSortedAsync(한도 7)**: 리더보드 갱신 90초 주기가 4를 쓴다. 인원 3명 이하일 때 주기를 늘릴지(수치 변경).
5. **파티 토픽 수신 한도(서버 수 비례)**: 원격 초대 · 좌석 메시지가 모든 서버로 간다. 서버 수가 많아지면 초대 연타가 토픽 한도를 먹고 메시지가 버려진다(초대만 유실 - 좌석은 하트비트가 맞춤). 서버당 원격 초대 발행 상한(예: 분당 20)을 둘지.
6. **약한 잠금의 남은 손실**: 두 서버가 동시에 진행하면 늦게 읽은 쪽 진행은 저장 안 된다(덮어쓰기 대신 손실). 강한 잠금(MemoryStore 세션 키 · 기다리고 막기)으로 갈지 - 출시 뒤 `SaveSessionLockWait` 음수(안 풀림) 비율을 보고 정하는 것을 추천.
7. (보고) 로드 중(잠금 대기 10초 포함) 나간 사람에게 `PlayerProfile.init`이 그대로 돈다 - 저장은 안 되므로 데이터 손상은 없고 메모리만 남음.
8. (보고) 알파 통계 요약은 모든 서버가 종료 때 한 키(`summaries`)에 쓴다 - 업데이트 배포로 서버가 한꺼번에 닫히면 같은 키 경합 · 키당 쓰기 4MB/분에 걸려 통계 일부가 빠질 수 있다(게임 데이터 무관).
9. (보고) 기존 하네스 드리프트: `monetize_test` 32/34(v56 기대값 - 지금 v61 · 기대값 갱신 필요) · `dupe_test` 시작 에러(`CodexRules` 등 새 모듈 · prelude에 `CFrame.fromMatrix` · `Vector3.xAxis` 없음 · `TextData` 분할의 `require(script.Parent[name])`) - 이번 변경과 무관(임시 prelude · HEAD TextData로 확인).
