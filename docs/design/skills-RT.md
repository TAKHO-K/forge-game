# R · T 스킬 설계 검토 (D0 · 2026-09-25)

- 원문: `docs/direction/0925-user-direction.md` 3장. 이 문서는 원문 의도를 먼저 그대로 옮기고(§1), 그 다음에 현재 코드 기준으로 검토한다(§2 ~ §9).
- 현재 상태 근거: `docs/phase/D0-audit.md` (a) · 1장 대조표 · 부록 A.
- 이미 결정된 규칙은 깨지 않는다: 보이는 장판 = 실제 판정 · 회피 부등식 · 중앙 금지 구역 · k 의존 값은 힘 비율로 데이터에 · 치유사 3+1 = 딜러4의 100 ~ 105% · 최고 기록 = 보스 클리어 기준 · 리더보드 이론 최소 시간.
- 모든 새 스킬은 CLAUDE.md 규칙대로 **effects 조각의 조합(데이터)** 으로 만든다. 스킬 전용 함수는 만들지 않는다. 새 조각이 필요하면 조각을 추가한다(아래 §8에 목록).

## 1. 원문 의도 (사용자 문서 3장 요약 - 뜻은 바꾸지 않았다)

**공통**
- 상호작용 키 F 등 필요한 키를 빼고 **R = 세 번째 스킬, T = 궁극기**.
- 궁극기 게이지: 일반 스테이지에서는 이동해도 유지되고 채워 두면 쓸 수 있다. **보스 스테이지에 들어갈 때만 0으로 초기화.** 보스 패턴을 피하거나 시간이 흐르면 차고, 공격해도 찬다. 오버워치처럼 직업마다 차는 속도가 다르다.
- 궁극기는 직업 특징을 살린 정말 유용한 스킬이어야 한다. 딜이면 딜이, 유틸이면 유틸이 확실히 좋아야 한다.
- **R은 Q/E가 비워 둔 역할을 채우고, T는 그 직업의 최종 정체성을 폭발시킨다.**
- 이동기 · 회피기가 늘면 보스가 쉬워지므로 보스 난이도 · 패턴을 함께 올린다. 큰 보스는 올라타서 공격하는 것도 가능할 수 있다.
- 목표: "공격력이 다른 5직업"이 아니라 **"보스 패턴을 푸는 방법이 다른 5직업"**. 궁극기를 누르면 파티원이 "저 직업이 자기 역할을 한다"고 한 문장으로 느껴야 한다.

**궁극기 게이지 충전(원문)**: 도적 = 피해량 + 표식 대상 공격 + 위험한 근접 공격 / 궁수 = 피해량 + 약점 적중 + 덫 적중 / 전사 = 피해량 + 받은 피해 + 포효로 전투 지속 / 치유사 = 치유 + 부활 + 아군 보호 / 성기사 = 방패로 차단 + 맹세로 대신 받기 + 도발 성공. → 게이지를 빨리 채우려고 역할을 버리는 현상을 줄인다.

**도발 예외(원문)**: 즉사 패턴 · 맵 전체 전멸기 · 핵심 기믹 · 페이즈 전환 · 기믹 전용 패턴 · 이미 시전 불가능한 패턴 · 특정 조건을 만족해야 나오는 패턴.

## 3. 궁극기 게이지 설계 검토

### 3-1. 규칙 (원문 + 제안)

| 규칙 | 원문 | 제안 · 이유 |
|---|---|---|
| 범위 | 0 ~ 100 | 서버가 가진다(`PlayerState` 칸 하나 + 출처별 충전 로그). 클라는 표시만 |
| 일반 스테이지 | 이동해도 유지 · 채웠으면 사용 가능 | 유지. 단 **사냥 중 충전 속도는 보스전의 ⅓** 제안 - 사냥에서 몇십 초마다 궁극기가 나오면 사냥 속도 · 경제(EconSim)가 바뀐다 |
| 보스 진입 | 0으로 초기화 | 유지. **전멸 리셋 때도 0**(재도전마다 같은 조건 - 리더보드 공정성) |
| 사망 | (원문 없음) | 유지(0으로 안 만든다). 부활 · 성역 부활을 벌하지 않기 위해 |
| 공통 충전 | 시간 · 패턴 회피 · 공격 | 시간 = 보스전 중 초당 일정량. 회피 = 서버가 이미 아는 사건만 쓴다: 파동 회피 기록(`BossPatterns.updateWaves`) · 장판 안에 있다가 판정 순간 밖(텔레그래프 판정). 공격 = 피해량 비례 |
| 직업별 충전 | §1 표 | 직업 역할 행동이 공통 충전보다 크게. 예: 치유사 = 치유량 ÷ 최대체력 · 성기사 = 막은 피해 ÷ 최대체력. 전부 **최대체력 비율**로 정규화 → 스테이지와 무관(k 의존 값 없음) |

### 3-2. 보스전 1회당 사용 횟수 목표

- `D0-audit.md` (e)에서 제안한 긴장감 목표(첫 도전 솔로 45 ~ 90초)를 기준으로 **보스전 1회에 1번, 긴 싸움(파훼 전)에서 2번**.
- 역산: 첫 궁극기 30 ~ 45초. 시간 충전만으로 100초(= 1%/초)면 평균 플레이어가 역할 행동으로 나머지를 채워 35초 안팎에 첫 사용. 직업별 속도 차이는 ±20% 안(오버워치식 차이는 두되 "누가 두 번 쓰는" 차이는 안 만든다).
- **주의**: 지금 모형에서는 보스가 1 ~ 5초에 죽는다(`D0-audit.md` (e)). 이 상태에서 게이지를 넣으면 보스전에서는 궁극기를 못 쓰고 사냥에서만 쓴다. **보스 난이도 조정(로드맵 G2)이 궁극기보다 먼저**여야 한다.

### 3-3. 밸런스 영향

| 대상 | 영향 | 처리 |
|---|---|---|
| 치유사 3+1 버프 17.36% (`PartyConfig.healerBuffFraction`) | 도적 · 궁수 · 검사 T가 딜 궁극기라 딜러 4의 보스 DPS가 오른다. 치유사 T(성역)는 딜이 0이라 "딜러 3 + 치유사 1 ÷ 딜러 4" 비가 떨어진다 → 100 ~ 105% 규칙이 깨진다 | 궁극기 평균 기여(보스전 1회 1번 가정)를 BalanceSim 로테이션에 넣고 `healerBuffFraction`을 다시 푼다. 치유사 R의 딜링모드 변환(암흑 별똥별)도 딜 쪽에 넣는다. 파티 6조합 전부를 같은 검사기(`P3dVerify.lua:177` · `EconSimReport.lua:337`)로 |
| 리더보드 이론 최소 시간 (`LeaderboardRules.minClearSeconds` = 보스 최대 HP ÷ 멤버 DPS 상한 합) | 궁극기 폭딜 구간이 DPS 상한을 넘으면 **정상 클리어가 too_fast로 거절**된다 | `memberDpsCap`에 "궁극기 1회분 추가 피해 ÷ 싸움 시간" 몫을 더한다. 게이지 최대 충전 속도로 계산한 **궁극기 사용 가능 횟수 상한**을 식에 넣는다(데이터로) |
| 받는 피해 감소 합성 | 성벽 · 포효 · 맹세 · 회전베기 · 대시 | 결정 1의 하한 0.25가 막는다. 성역(HP 1 바닥)은 배율이 아니라 **바닥 규칙** - 배율과 따로 둔다 |
| 경제(사냥) | 사냥 중 궁극기 = 사냥 속도 증가 | 사냥 충전 ⅓ 제안 + EconSim에 "궁극기 평균 가동" 항 추가 |
| 회피 부등식 · 보이는 장판 | 궁수 덫 감속 · 도발 패턴 앞당기기가 패턴 타이밍을 바꾼다 | 덫 감속은 **보스 이동 속도만**(패턴 전조 · 판정 속도는 그대로). 도발 뒤 "즉시 시전"도 **전조는 그대로 보여 준다**(전조를 줄이면 회피 부등식 위반) |

## 4. 치유사 T 생명의 성역 - HP 1 바닥 vs 즉사 · 전멸기

- 원문: 성역 안에서는 HP가 1 아래로 안 내려간다. 즉사 · 전멸 기믹은 못 막는다. 다른 사람이 죽어도 자신은 살 수 있다(4힐러 전략). 기믹을 실패했으면 일정 시간 뒤 전멸 기믹을 다시 시도한다.
- 현재 코드에 **즉사 · 전멸 등급이 없다**(§2-5). 그래서 이 설계는 보스 쪽 작업이 먼저다.

| 피해 등급(새 데이터 필드 제안: `lethality`) | 예 | 성역 | 쉴드 |
|---|---|---|---|
| `normal`(기본) | 평타 · 일반 패턴 · 지금의 기믹 실패 55% | **HP 1에서 멈춤** | 흡수 |
| `execute`(즉사) | 새 패턴: 판정에 걸리면 HP와 무관하게 사망 | 못 막음 | 못 막음(`ignoresShield`) |
| `wipe`(전멸기) | 새 기믹: 해법 실패 시 아레나 전원 `execute` | 못 막음 | 못 막음 |

- **4힐러 전략이 성립하는 조건**: `wipe`는 "해법을 수행한 사람만 산다"형이 아니라 "파티 전체 실패 → 전원"형이어야 성역으로도 못 버틴다. 원문의 "다른 파티원이 죽어도 자신은 생존"은 `normal` 누적 피해(광역 난사) 쪽 이야기다 → 성역은 **광역 `normal` 폭탄**을 버티는 도구, `wipe`는 **해법으로만** 넘는 벽.
- 전멸기 실패 뒤 재시도: 기믹 실패 → 전원 사망이면 지금 규칙상 전멸 리셋(보스 HP 풀회복)이다. 원문 "일정 시간 뒤 다시 전멸 기믹 시도"는 **살아남은 사람이 있을 때(성역이 `normal`만 막으므로 사실상 `wipe`에서는 없음)** 의 이야기로 읽힌다 [해석 - 결정 필요]. 제안: `wipe` 실패 = 전원 사망 = 리셋(지금 규칙 유지). 성역으로 버틴 `normal` 광역 폭탄 기믹은 실패 판정이면 **N초 뒤 같은 기믹 재시전**(`BossScheduler` 기믹 쿨을 실패 시 짧게 - 데이터).
- 끝날 때: 생존자 대량 회복 · HP 1이던 사람 일정 회복 · 성역 안에서 죽은 사람(= `execute`로 죽은 사람) 1회 자동 부활(원문 추천). 부활 규칙은 §5와 같은 "영혼 상태"를 전제로 한다.
- 표시: 성역 경계 = 바닥 원(보이는 장판 = 실제 판정 - 원 안 판정은 발 기준 수평 거리, 기존 `Reach` 규칙).

## 6. 성기사

### 6-1. 도발(E) 예외 목록 - 현재 데이터로 옮기면

| 원문 예외 | 지금 데이터에서 해당하는 것 | 제안 |
|---|---|---|
| 즉사 · 맵 전체 전멸기 | 없음(새로 만들 `execute` · `wipe`) | `lethality ≠ normal`이면 도발 불가 |
| 핵심 기믹 · 기믹 전용 패턴 | `category = "gimmick"`(우선순위 100 - 서리 roar · 심해 flood · 수정 split · 전갈 shell · 폭풍 overcharge) | 도발 불가 |
| 페이즈 전환 | 없음(격노 = HP 20% 이하 전역 쿨 2.5초 변화뿐) | 페이즈 기믹을 만들면 `category = "phase"` → 도발 불가 |
| 이미 시전 불가능한 패턴 | 스케줄러 쿨 · 직전 스킬 연속 금지 | "즉시 시전할 비기믹 패턴" 후보에서 쿨 안 찬 것 제외 |
| 조건부 패턴 | 전갈 여왕 stab(돌진 2회 signature)처럼 대상 · 순서가 정해진 패턴 | 데이터 플래그 `tauntable = false` |
| 나머지 | `normal` · `signature` | 도발 가능. 도발하면 **지금 시전 중인 패턴 취소 → 성기사를 바라봄 → 쿨 찬 `normal` 1개 즉시 시전(전조는 정상 길이)** → 도발 내부 쿨 |

- 기본값은 **도발 불가**(`tauntable`을 켜야 가능)로 두는 편이 안전하다. 새 보스를 추가할 때 실수로 기믹이 끊기지 않는다.

### 6-2. 방패(Q) - "진짜로 숨을 수 있어 보이게"
- 원칙이 "보이는 장판 = 실제 판정"과 같은 방향이다: **방패 모델이 가리는 곳 = 막히는 곳**. 판정 = 패턴 판정점(발 기준)에서 보스(또는 투사체 원점)까지 선분이 방패 상자를 지나면 막음. 원형 · 도넛 · 파동처럼 "원점이 없는" 판정은 방패 뒤 부채꼴 그림자로 정의해야 한다(새 규칙 - 결정 필요).
- 금 단계(100 · 60 · 30 · 10 · 0%)는 P3d-F의 금 간 단상 표현(굵은 금 · 위험색 · 흔들림 · 먼지)을 그대로 재사용할 수 있다.

### 6-3. 범위
- 성기사는 직업 추가라 비용이 가장 크다: ClassData · SkillData(Q/E/R/T) · 무기 모델(뿅망치 · 방패) · 공격 모션 · 탱커 훅 채우기(`tank.defaultWeightFactor`) · 파티 6조합 → 10조합 이상 밸런스 · 리더보드 직업 보드 추가 · 튜토리얼.
