## ④ 반짝이 몹 [3]

### 4-1 적용
- **드랍표**: 영웅 55 · 전설 36 · 유물 8.8 · 고대 0.195 · 태초 0.005%. 태초 · 고대 = 첫 클리어의 절반이다. 등급 순서대로 굴린다(옛 `pairs` 순서 없음 → `rollGrade`). 확률 공개(`DropTable.disclosure().sparkle`)에도 넣었다.

- 새 표 + 지금 출현(0.5%)은 **1인 태초를 약 40% 늘리고(개당 약 1,400h), 10만 h에서 하루 알림 약 58회로 45회를 넘는다.** (지시의 "약 1,800h/개"는 이 모형으로는 사냥 + 첫 클리어만 2,350h다.)
- **출현 빈도를 낮춘 안 = 0.5% → 0.1% + 골드 125마리분**(사냥 골드 몫 11.1% 유지). 1인 태초 -12%, 하루 39.5회다. 반짝이는 상위 1% 기준 시간당 5.8 → 1.2마리가 된다.

## ⑤ 파티원 예외 [4]

- **규칙**: 같은 파티끼리는 막힘에서 뺀다(`MobShare.sameParty` → `blocksAgainst`). 보상 자격(기여 10% · 같은 스테이지 · ≤ 기준)과 어그로 필터(`tooWeakFor` - 약한 파티원이 기준 몹에 즉사하지 않게)는 그대로다.
- **구현**
  - 파티 번호 = Player Attribute `PartyId`다. `PartyState`의 `partyOf`를 대리 표로 바꿔 결성 · 합류 · 복귀 · 탈퇴 · 끊김 모든 쓰기에서 같이 맞춘다.
  - 클라 자물쇠 문자열에 파티 번호 칸을 더했다(`userId,stage,level,rebirth,party,만료`).
- **시뮬(`C1Sim`)**: a ~ n 전부 C1-fix5와 같은 값이다(a -4.2% · b +2.1% · … · j-2 +9.5% 주의 · n · n-low 0).

| 새 행 | 결과 |
|---|---|
| o: n의 두 계정이 같은 파티 - 강한 파티원이 초보 파티원 몹을 같이 침 | 초보 가치 498/분 = 솔로 185의 **×2.7**(파티 버스 · 의도 - 검증 판정에서 제외) · 강한 쪽 498/분 · 막힘 false |
| o-other: 다른 파티끼리 | 0(= n · 막힘 유지) |

- 파티 버스 자체는 전에도 있었다(강한 쪽이 먼저 치면 초보는 follower로 10% 채움). 이번 예외는 **누가 먼저 쳤는지에 따른 차이를 없앤 것**이다.
