## 구조 요약
- 키: 계정 `Acct_<UserId>` + 캐릭터 `Char_<UserId>_<번호>` · 옛 `Player_<UserId>` = SlotSave 켬 동안 **읽기만**(legacy 보존). 세션 잠금 = 계정 키. 저장 버전 74.
- 메모리 안 프로필 모양은 그대로(저장 계층에서만 나누고 합침) → 기존 게임 코드 변경 최소.
- 스위치 `SlotSaveData.enabled`(끔 = 옛 키 · 켜 둔 동안 진행은 계정 + 모든 캐릭터를 옛 모양으로 합쳐 읽음 = 손실 0) · `legacyRecheck`(껐다 다시 켤 때 운영이 켬 → 옛 키에서 다시 이관) · `mergeOnDisable`.
- 직업 선택 스위치(되살리기 = true): `LegendData.avatarPreview`(= ClassSelectAvatarPreview) · `LegendData.transform`(= ClassSelectTransform) · 메뉴 건너뛰기 옵션 `MainMenuData.skipMenuOption`.

## EconSim 영향
- 실행 안 함 - 근거: EconSim은 한 캐릭터(한 직업) 진행만 흉내 낸다. 그 경로에서 바뀐 것은 없다(골드 · 수련 · 가격 기준 = 그 캐릭터 = 옛 "계정 최고"와 같은 값). 공유 범위 변경은 **여러 캐릭터를 키우는 유저**에게만 영향(두 번째 캐릭터는 골드 0 · 수련 0부터 - 옛 = 공유 골드 · 수련으로 빨랐다). 이 경로를 재려면 EconSim에 "두 번째 캐릭터" 프로필을 새로 넣어야 한다(다음 큐 후보).
