## 1. 2단 높이 후보별 수치 [계산]

설계 두 가지를 비교한다.
- **A 고정형**: 2단을 누르면 언제든 위로 h2만큼 오르는 속도 √(2g·h2)를 준다(세로 속도는 더하지 않고 **바꾼다**).
- **B 상한형(권장)**: 2단 속도 = √(2g·min(h2, H − y)). y는 지금 발 높이(이륙한 지면 기준), H = 7.2(1단 최고 높이)다. "2단은 1단보다 낮게"를 **절대 높이**로 읽은 해석이다. 1단 정점에서 누르면 거의 안 오르고, 내려오는 중에 누르면 h2만큼 다시 오른다.

| 항목 | 1단만(현행) | A 50%(3.6) | A 60%(4.32) | A 70%(5.04) | B 상한 7.2(h2 50~70% 공통) |
|---|---|---|---|---|---|
| 발 최고 높이(정점에서 2단) | 7.2 | **10.8** | **11.52** | **12.24** | **7.2** |
| 체공(정점에서 2단) | 0.542 | 0.794 | 0.823 | 0.851 | 0.542 |
| **체공 최대**(누르는 높이 y\* = (7.2 − h2)/2) | 0.542 | **0.932** | **0.965** | **0.997** | 0.932 / 0.966 / 0.998 |
| 체공 최대 + 공중대시(두 기술을 함께 쓸 때) | 0.954(현행) | 1.337 | 1.374 | 1.409 | 1.337 / 1.374 / 1.409 |
| 발 높이 > 8인 시간(최대) | 0 | **0.338** | **0.379** | **0.416** | **0** |
| 발 높이 > 6.5인 시간(몬스터 평타가 빗나가는 구간 - §7) | 0.169 | 0.552 | 0.589 | 0.622 | 0.338 |
| 파동 입력 창, 한 겹(속도 24) = 체공 + 4/24 | 0.707(데이터 0.71) | 1.099 | 1.132 | 1.164 | 1.099 / 1.133 / 1.165 |
| 파동 입력 창, 한 겹(방전 36 · 20) | 0.653 · 0.742 | 1.043 · 1.132 | 1.076 · 1.165 | 1.108 · 1.197 | A와 같음 |
| 파동 입력 창, 두 겹(해일 - 겹 간격 = 두께 ÷ 속도라 창 = 체공) | 0.54 | 0.932 | 0.965 | 0.997 | A와 같음 |

- 입력 창은 "늦은 2단"으로 구제받는 경우를 포함한 최대값이다. 너무 일찍 뛰었다가 착지하기 전에 2단을 누르는 것이 이단점프의 핵심 이득이다.
- B는 체공 상한이 A와 같다(체공이 가장 긴 누름 높이에서 y\* + h2 = 5.4 ~ 6.1 < 7.2라 상한에 안 걸린다). 대신 높이에 걸린 불변식은 1단과 **같다**.

## 2. 점프 패턴 재조정 필요량

**"이단점프로 두 박자를 한 번에 넘는다"의 조건.** 한 번 떠 있는 동안 두 박자의 모든 띠를 공중에서 만나야 한다.
필요 체공 = (다음 박자 마지막 겹의 띠가 닿기 시작하는 시각) − (앞 박자 첫 겹의 띠가 다 지나간 시각). 이 값을 거리 d = 0(보스 몸통은 충돌이 없어 붙어 설 수 있다 - `BossData.lua:360`) · 8(검사기 standoff, 각 보스 `chaseStopDistanceStuds = 8`) · 140.6(`waveMaxRadiusStuds`)에서 재고 가장 작은 값을 쓴다.
막으려면 **필요 체공 ≥ 최대 체공 + 여유 0.1**이어야 한다.
회피 부등식의 "다시 뛰기" = 박자 간격 ≥ 0.5 + 0.54 × 1.25 = 1.175(`shared/BossSkillMath.lua:185-208`)는 1단 기준으로 그대로 둔다. 간격을 늘리기만 하므로 자동으로 계속 성립한다.

| 패턴 · 박자 | 지금 간격 | 필요 체공(최소 거리) | 다시 뛰기(≥1.175) | 금지 50 / 60 / 70%(최대 체공 0.954 / 0.965 / 0.997) | 허용 50 / 60 / 70%(1.337 / 1.374 / 1.409) |
|---|---|---|---|---|---|
| 진동파 1→2 | 1.6 | 1.433(거리 무관) | 1.600 | 안전(여유 0.48 / 0.47 / 0.44) | 겨우 안전(0.096 / 0.059 / 0.024) → **1.65 / 1.65 / 1.70** |
| 진동파 2→3 | 1.25 | 1.083 | 1.250 | 안전(0.129 / 0.118 / **0.086**) → 70%만 **1.30** | **깨짐**(−0.25 ~ −0.33) → **1.65 / 1.65 / 1.70** |
| 해일 1→2(30→24, 2겹) | 1.5 | 1.533(d=0) · 1.600(d=8) | 1.433 | 안전(0.54 이상) | 안전(0.196 / 0.159 / 0.124) |
| 해일 2→3(24→18, 2겹) | 1.5 | 1.556(d=0) · 1.667(d=8) | 1.444 | 안전 | 안전(0.219 / 0.182 / 0.147) |
| 방전 1→2(36→20) | 1.3 | **1.189(d=0)** · 1.367(d=8) | 1.478 | 안전(0.235 / 0.224 / 0.192) | **깨짐**(−0.15 ~ −0.22) → **1.55 / 1.60 / 1.65** |

- "금지" = 이단점프를 쓴 뒤 공중대시 불가 + 공중대시를 쓴 뒤 2단 불가(현행 1단 + 공중대시는 그대로 둔다). "허용" = 현행 공중대시를 그대로 두고 이단과 함께 쓸 수 있게 한다.
- 방전은 d = 8 기준이면 여유가 커 보이지만 보스에 붙어 서면(d = 0) 필요량이 1.189로 줄어든다. 검사기는 standoff만 재므로 이 경우를 못 본다. 새 검사를 넣을 때 d = 0도 넣어야 한다 [계산 · 붙어 서는 플레이는 추정].
- 속도와 두께로는 거의 못 번다. 같은 속도끼리는 필요량이 간격 − 두께/속도라서, 속도를 24 → 36으로 올려도 +0.056, 두께를 4 → 2로 줄여도 +0.083뿐이다. 게다가 두께를 줄이면 1단 입력 창도 준다. 전조(1.2)는 첫 박자에만 걸려 무관하다. **실제로 조정할 값은 박자 간격뿐이다.**
- 기존 감사(§7)는 방전의 필요량을 d = 8 기준 1.37로, 해일은 앞 박자 끝 기준으로 1.30으로 셌다. 겹과 거리를 다시 세면 해일은 더 안전하고 방전은 덜 안전하다.

**새 박자 값 제안**

| 경우 | 진동파(느림 · 느림 · 빠름) | 해일 | 방전(천둥 · 메아리) | 구속 시간 변화 |
|---|---|---|---|---|
| **금지 + 2단 50~60%(권장)** | 1.6 · 1.25 **그대로** | 그대로 | 그대로 | 0 |
| 금지 + 70% | 1.6 · **1.30** | 그대로 | 그대로 | +0.05초 |
| 허용 + 50~70% | **2.0 · 1.7**(빠름 박자가 1.65 이상이어야 해서 리듬을 유지하려면 느림 박자도 늘려야 함) | 그대로 | **1.55 / 1.60 / 1.65** | 진동파 +0.85초 · 방전 +0.25~0.35초 |

- "허용"은 진동파의 "빠름" 박자가 1.65 이상이어야 해서 리듬 성격이 약해진다. **공중대시를 보류한다면 "이단점프와 함께 쓰기 금지"로 두는 것이 값 조정이 가장 적다.**
- 검사기 보강 제안: `BossSkillMath.dodgeChecks`의 ring 분기(185-208)에 "이단 한 번에 두 박자 불가" 검사를 추가한다. 가용 = 위 필요 체공(d ∈ {0, standoff, WAVE_MAX}), 필요 = `mechanics.dodge.doubleJumpMaxAirSeconds`(새 데이터 칸, 0.997처럼 계산해 적음) + 여유. 기존 "다시 뛰기"는 1단 0.54 기준으로 둔다.

**단상 올라가기 · 범람**
- 단상(윗면 3.5, `BossArenaMapData.lua:63`): 1단(7.2)으로 이미 오른다. 이단점프는 늦게 뛰어도 오를 수 있게 해 줄 뿐 요구 사항은 바뀌지 않는다. 무너지는 단상에서 떨어지는 중 2단을 쓰는 경우는 그 파동이 이미 면제라(`BossPatterns.lua:750-757`) 이득이 없다.
- 범람: 영향 없음(§0).

## 3. 바닥 판정(발 기준 높이차 ≤ 8)에 주는 영향

근거: 원 · 강타 · 직선 · 돌진 · 마무리 · 구조물이 전부 `Reach.sameLayer(v.feet, 판정 지면)`을 쓴다(`BossPatterns.lua:497 · 712 · 1045 · 1254 · 1383 · 1693`, 허용치 `TerrainConfig.lua:47-49` 8).

- **A 고정형으로 발 최고 높이를 8 이하로 두려면 h2 ≤ 0.8이어야 한다** [계산: 7.2 + h2 ≤ 8]. 이때 최대 체공은 0.765초라 이단점프로서 거의 의미가 없다. **"2단을 낮게 잡는 것"만으로는 판정 규칙을 그대로 둘 수 없다.**
- **B 상한형이면 규칙을 바꿀 필요가 없다.** 발은 절대로 7.2를 넘지 않고(> 8인 시간 0) 체공만 길어진다. 상한을 7.9까지 올려도 발은 8 이하지만, 루트가 단상 위에서 3.5 + 7.9 + 3 = 14.4가 되어 벽 14 위로 대시 광선이 지나간다(§4). **그래서 상한은 7.2로 둔다.**
- A를 택하면 필요한 규칙 변경:
  - 보스 바닥 판정 전용 높이 허용치(예: `BossArenaMapData.judgeHeightStuds = 7.2 + h2 + 0.8`, 50% 11.6 · 70% 13)를 새로 두고, 위 여섯 곳의 `Reach.sameLayer(v.feet, …)`에 넘긴다. 사냥터 8은 그대로 둔다.
  - "보이는 장판 = 판정"과의 관계: 탑다운 카메라에서는 XZ가 장판 안이면 "장판 위에 떠 있는 것"으로 보인다. 그래서 허용치를 올려도 원칙에는 오히려 맞는다. 8은 절벽 층 구분용이었고, 보스 아레나에는 8을 넘는 걸을 수 있는 층이 없다(둔덕 1.5 · 단상 3.5 · 기둥 ≤ 8 - `BossArenaMapData.lua:86-98 · 128-146`).
  - 다만 허용치를 올리면 공중에서 맞고 뜨는 넉백의 시작 높이도 같이 올라간다(8 → 12.24, §4). 그러면 벽도 함께 올려야 한다.
- **기존 구멍 [계산] - 이단점프와 무관하게 이미 있음**: 단상(3.5) 위에서 1단 점프만 해도 발이 아레나 바닥 기준 8을 넘는 시간이 **0.332초** 있다. 그동안 보스 중심 원 · 돌진 · 직선 · 마무리가 빠진다. 판정 기준이 아레나 바닥(`st.floorY` · `footOf(보스)`)이기 때문이다. 이단점프가 있으면 이 시간이 A에서 0.71~0.79초, B에서도(상한을 이륙 지면 = 단상 기준으로 재면) 0.66초로 길어진다. 제안: 바닥 판정의 기준 높이를 "플레이어 발밑 지면(단상 윗면 포함, 판정 지면 + 8 이내일 때)"으로 바꾼다. 또는 단상 위에서는 B 상한을 아레나 바닥 + 7.2로 잰다.

- 걸어서 넘기: 필요한 수평 속도 54.5 / 40.1 / 36.5 stud/s(50 / 60 / 70%). 신속 옵션에 상한이 없어서(`OptionData.lua:52` cap = nil, 최대 약 104) **실제로 가능하다**.
- 대시로 뚫기: 루트가 14를 넘는 순간(발 > 10.5) 대시 광선이 벽을 못 맞힌다(`server/DashEndpoint.lua:25-66` 벽 Raycast). 도착점이 벽 밖이 되고, 클라 트윈은 충돌을 무시한다. 필요한 걷기 속도는 12.5 / 11.7 / 11.1로 **기본 16이면 된다.** 공중대시를 "허용"으로 두면 기본 스탯으로 바로 이탈한다.
- 결과: ③ 복귀(0.25초 폴링, `server/BossArenaContainment.lua:57-102`)가 잡아 스폰 자리로 되돌린다. 이것은 그물일 뿐이고 "③ 0회" 불변식(3행)은 깨진다.

**"넉백 중 불가"가 ①을 지키는가**
- 넉백은 클라가 `humanoid.PlatformStand = true`로 처리한다(`BossStormView.lua:196-203`, 회오리 `lift` 131-151). 엔진은 PlatformStand 중에 점프를 받지 않는다 [추정]. 이단점프 코드도 PlatformStand를 금지 조건으로 봐야 한다.
- PlatformStand는 "지면에서 떴다고 가정한 체공 + 0.1" 뒤에 풀린다. 공중에서 맞았으면 풀린 뒤에도 잠깐 떠 있다(발 8에서 맞으면 풀릴 때 발 ≈ 1.6) [계산]. 그래서 **"넉백을 받은 뒤 착지할 때까지 2단 불가"**(플래그를 Landed에서 해제)로 정해야 한다. PlatformStand만 보면 부족하다.
- 이렇게 하면 넉백과 2단은 겹치지 않는다. 넉백 정점은 이단점프와 무관하게 **판정 높이 상한 8 + 7.5 = 15.5**로 묶인다. 이 값은 이미 14를 넘는다(기존 문제). 다만 수평 착지점은 ②가 자르고, 포물선이 벽 안쪽 착지점을 향한 직선이라 넘어가지는 않는다. 공중 시작이라 실제 체공이 약 20% 길어져 수평이 12 → 약 14.4까지 늘 수 있는데, 안쪽 여백 3 안이다 [계산].
- A 고정형에 §3의 판정 허용치 상향(예: 13)까지 더하면 넉백 시작 높이가 12.24까지 올라가 정점이 19.7이 된다.

**필요한 벽 높이 · 조치**

| 설계 | 조치 |
|---|---|
| **B 상한 7.2** | 없음(현행 불변식 그대로). 넉백 중 · 넉백 뒤 착지 전 2단 금지만 넣는다 |
| A 조합 금지 | 걸어 넘기 방지 - 벽(또는 투명 충돌 연장) ≥ 단상 3.5 + 7.2 + h2 + 여유 → 50%: 15.5 · 60%: 16 · 70%: 17 |
| A 허용 | 대시 광선까지 막기 - 루트 기준 ≥ 17.3 / 18.02 / 18.74 + 여유 → **19~20**. 권장은 보이는 벽 14 위에 투명 충돌 파트(CanCollide · CanQuery 켬, 대시 Raycast에 맞게)를 20까지 두는 것. 판정 허용치를 올리면 ≥ 21(넉백 19.7) |
| 공통(기존 문제) | `ArenaContainment.simulate`에 "공중 피격 넉백(시작 높이 = 판정 상한)" 사건을 넣는다. ① 주석의 11 < 14를 "8 + 7.5 = 15.5"로 고쳐 다시 셈할지 결정이 필요하다 |

## 5. 서버 높이 검증 설계

현재 서버 이동 검증은 없다(기존 감사 §6). 서버가 공중 여부를 판단할 때는 클라 Humanoid 상태를 믿는다(`BossPatterns.lua:107-122`).

**무엇을 재나**
- 기준 = `lastSupportY`(플레이어별). 폴링할 때마다 `humanoid.FloorMaterial ~= Air`이면(서버에서 약 0.2초 늦게 보임 - `BossPatterns.lua:104-106` 주석) 그때의 발 Y를 기록한다. 발판이 지면 폴더에 있는지는 따지지 않는다. `GroundProbe` 폴더만 보면 오두막 지붕 · 나무 줄기 · 기둥 위에 선 사람을 오탐한다(나무 줄기 · 오두막은 지면 폴더 밖이다 - `server/ZoneTerrain.lua:337-397`).
- 위반 값 = 발 Y − lastSupportY.
- 허용치(새 데이터 칸, 예: `TerrainConfig.jumpGuard`):
  - B 상한 7.2: 7.2 + 여유 1.0 = **8.2**
  - A: 7.2 + h2 + 1.0 = 11.8 / 12.5 / 13.2
  - 여유 1.0은 복제 지연과 보간을 덮기 위한 값이다 [추정 - 실측 권장].
- 한도를 넘었을 때만 확인용 Raycast 1회: 루트에서 아래로, 캐릭터는 제외하고 충돌 파트 전부. 지면 거리가 HipHeight + 1 + 0.5 이하면 무언가 위에 서 있는 것이므로 기준을 갱신하고 통과시킨다(FloorMaterial 지연 대응).
- 선택: 공중 체류 시간 검사. 계속 공중(FloorMaterial = Air)이고 내려가지 않는 상태가 (최대 체공 + 대시 0.3 + 0.7) ≈ 2초를 넘으면 호버 의심.

**예외**

| 예외 | 처리 | 출처 |
|---|---|---|
| 넉백 · 회오리 · 구조물 파편 | 서버가 보낸 순간 `exemptUntil = now + 체공 + hold + 0.5`를 둔다(검사 건너뜀) | `BossPatterns.lua:603-637` runHitEffects · `BossArenaMap.lua` fireBreak(topBreak 5) |
| 대시(지상 · 공중) | 세로로 오르지 않으므로(도착점 Y = 시작 Y, 지면 추종은 경사 한계 안) 예외 불필요. 공중대시 0.3초 정지도 높이는 그대로다 | `DashServer.server.lua:66-78` |
| 단상 · 구조물 · 계단 · 지붕 | 기준이 lastSupportY라 저절로 처리된다(올라선 순간 기준이 오른다) | - |
| 순간이동(③ 복귀 · 심연 복귀 · 입장 · 재도전 · 리스폰 · 포탈) | `HeightGuard.reset(player)`를 호출하고 1초 유예. 호출을 빼먹는 경우를 대비해 한 폴링에서 위치가 50 넘게 변하면 자동 초기화(정상 최대: 104 × 0.25 + 대시 16 = 42) | `BossArenaContainment.lua:83-86` · `TerrainServer.server.lua:39-45` · CharacterAdded |
| 잡힘 · 끼임(루트 Anchored) · 사망 | 검사 건너뜀 | `PlayerState.setAnchorHold` 315-327 |

**위반 시 처리**
- 연속 2번(0.5초) 넘으면 `lastSupportPos`로 되돌리고 속도를 0으로 만든다. 로그 "[forge-game] 높이 보정"을 남긴다. 추방은 하지 않는다.
- 보스전 중이면 그 판의 리더보드 기록을 무효로 표시한다(지금 유일한 부정 방지가 리더보드다 - `server/Leaderboard.lua:12 · 238`).
- 0.25초 폴링이 정점을 놓치는 것은 괜찮다(정상 점프를 오탐하지 않는 쪽). 날기 부정은 계속 떠 있으므로 0.5초 안에 잡힌다.

**주기 · 비용 · 합치기**
- 0.25초 × 전원. 평소에는 속성만 읽고 Raycast는 0번, 한도를 넘을 때만 1번이다. 16인이면 초당 64회 읽기로 무시할 만하다 [계산].
- **합치는 곳 권장: `TerrainServer.server.lua:62-73`의 심연 폴링**(같은 0.25초, 이미 모든 플레이어 · 모든 구역을 돈다). `BossArenaContainment`의 Heartbeat(92-104)는 보스전 멤버만 돌고, "③ 0회 = 정상" 로그 불변식이 있어 섞으면 뜻이 흐려진다. 검사 함수는 새 모듈(예: `server/HeightGuard.lua`)에 두고 TerrainServer 루프에서 부른다. 보호 여부는 `BossArenaContainment.isProtected`(44-46)를 조회한다.
- 한계: 이 검증은 "높이"만 본다. 서버 파동 회피는 클라가 보고한 Humanoid 상태(Jumping/Freefall)를 먼저 믿으므로(`BossPatterns.lua:113-116`), 상태를 조작하는 부정은 높이 검증으로 못 잡는다(별도 과제).

## 6. 구현 위치

**클라 입력(새 파일 제안: `client/DoubleJumpInput.client.lua` · 수치는 `shared/data/`의 새 JumpConfig 또는 TerrainConfig 플레이어 절)**
- 지금 저장소에는 점프 입력을 다루는 코드가 없다. `JumpRequest` · `ChangeState` · `JumpHeight`를 grep하면 검증 코드 1줄만 나온다. 공중 여부 판정은 `AttackInput.client.lua:202`에 선례가 있다.
- 입력: `UserInputService.JumpRequest`. Space · 게임패드 A · 폰 TouchGui 점프 버튼이 모두 이 신호를 낸다 [추정 - 로블록스 표준 이단점프 관례].
  - 누르고 있으면 매 프레임 반복 발생하는 것으로 알려져 있다 [추정]. 그래서 **"직전 JumpRequest와 0.1초 이상 떨어진 새 누름"만** 2단으로 센다. 그렇지 않으면 1단 버튼을 누른 채로 있으면 이륙 직후 2단이 자동으로 나간다.
- 조건: `humanoid:GetState()`가 Freefall(또는 Jumping이고 이륙 후 0.1초 이상) · 이번 체공에 2단 미사용 · 금지 조건 아님.
  - 턱에서 걸어 떨어진 Freefall에도 허용할지는 결정 사항이다. 허용한다면 기준 높이는 마지막 지면이다.
  - Landed · Running에서 초기화한다.
- 적용: **`root.AssemblyLinearVelocity = Vector3.new(v.X, v2, v.Z)`로 세로 속도만 바꿔 넣는다.**
  - `humanoid:ChangeState(Jumping)`은 엔진이 JumpHeight 7.2만큼의 속도를 넣을 가능성이 있어 "낮은 2단"이 깨진다 [추정]. 쓰지 않거나, 쓴다면 같은 프레임에 속도를 다시 덮어쓴다.
  - 상태는 Freefall 그대로라 서버 `isAirborne`이 공중으로 읽는다(`BossPatterns.lua:113-116`).
  - B 상한형은 v2 = √(2g·min(h2, 7.2 − (발Y − 이륙 지면Y)))로 계산한다.
- 공중대시 "금지" 처리: `DashInput.client.lua`의 대시 요청 경로에서 "이번 체공에 2단 사용"이면 요청하지 않는다. 2단 쪽에서는 "이번 체공에 공중대시 사용"이면 거절한다. 서버 `DashServer`(32-80)는 공중 여부를 모르므로 클라 규칙과 §5 감사로 막는다.

**금지 조건의 상태 출처**

## 7. 사냥터 영향(ZoneTerrainData)

사냥터는 tier1 · tier2 두 곳과 마을(spawn)뿐이다(`WorldConfig.lua:70-72`). 판정은 몬스터 평타 `Reach.within(루트, 몬스터 루트)`(`MonsterAI.server.lua:214`), 어그로 `Reach.sameLayer(루트)`(105), 추격 유지 `GroundProbe.sameGroundLayer`(337, 공중이면 발밑 지면)이다.

- **몬스터 평타 회피 [계산]**: 플레이어 루트는 발 + 3, 몬스터 루트는 발 + 1.5라서 **발 > 6.5면 평타가 빗나간다**.

- **새로 올라설 수 있는 곳**(1단 7.2로는 못 가고 A 10.8~12.24로 가는 곳):

## 8. 결론 · 권장안

1. **2단은 "상한형 7.2"(B)로 하고, h2는 50~60%로 한다.** 발 최고 높이가 1단과 같아서 바닥 판정 8 · 벽 14 · 대시 광선 · 사냥터 층 · 피뢰침 불변식이 모두 그대로다. 이득은 체공(0.54 → 0.93~0.97)과 늦은 구제 입력뿐이다.
2. **공중대시 보류 = "이단점프와 함께 쓰기 금지"로 해석한다.** 그러면 박자 값을 바꿀 필요가 없다(70%일 때만 진동파 빠름 박자 1.25 → 1.30). "현행 유지 + 함께 쓰기 허용"이면 진동파 2.0 · 1.7, 방전 1.55~1.65로 바꿔야 하고 리듬 성격이 약해진다.
3. 넉백: PlatformStand 중과 넉백 뒤 착지 전에는 2단 금지(클라 플래그).
4. 기존 문제 두 가지는 이단점프와 별개로 결정해야 한다: 단상 위 1단 점프의 바닥 판정 빠짐 0.33초, 공중 피격 넉백 정점 15.5 > 벽 14.
5. 서버 높이 검증: lastSupportY 기준, 허용치 8.2(B), TerrainServer 0.25초 루프에 합침, 넉백과 순간이동은 예외.
