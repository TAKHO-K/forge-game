# QUEUE-ALL9E1 메시 생성 시험 보고서(2026-10-04 밤 · 결과만 - 게임 적용 없음)

## 결론(맨 위)
- **도구 사용 가능**: Studio MCP `generate_mesh`가 이 환경에서 동작했다(글 설명 + 삼각형 상한 + 크기 상자 → 텍스처 입힌 MeshPart 1개).
- **의견: 지금 그대로는 장비로 못 쓴다 · 시안(콘셉트) 참고용으로만 쓸 만하다.** 이유 3가지:
  1. **색이 텍스처에 구워져 등급색 재사용 불가** - 8등급 × 4직업이면 생성을 32번 따로 해야 하고, 그때마다 모양이 바뀐다(아래 3번).
  2. **몸에 안 맞는다** - 어깨판이 R15 팔 위로 나오지 않고 몸통 폭(2.1 stud) 안에 생성됐다(요청 상자 3.4 무시). 앞면 껍데기 위주라 3/4에서 옆구리가 비어 보인다. 축별로 늘려 맞추면 가슴판까지 같이 늘어난다.
  3. **같은 설명으로 다시 만들면 모양이 크게 달라진다** - 세트 · 등급 사다리처럼 "같은 장비의 단계"를 만들기 어렵다.
- 비교 캡처 1장: `docs/phase/all9e1/captures/meshgen/meshgen_compare_look3_2k_4k_8k.jpg`(열 = LOOK3 | 생성 2,000 | 4,000 | 8,000 | 4,000 2회차 · 행 = 정면 17 stud · 3/4 · 정면 30 stud). 원본 = 같은 폴더 `raw_*.jpg`.

## 1. 시험 조건
- 대상: 대검 · 전설 · 갑옷(가슴판 + 어깨판). 설명(영문 입력): 카툰 중세 판타지 판금 가슴갑옷 · 크고 둥근 겹 어깨판 · 모든 판 테두리 굵은 금 · 가슴 중앙 패싯 호박 보석 · 주색 #D87828 에나멜 · 아래층 가죽 #5A3E2B 끈 · 벨트 · 로블록스 R15 몸통 비율 · 속 빔 · 머리 · 팔 없음.
- 분할 = 없음(한 덩어리) · 크기 상자 3.4 × 2.2 × 1.6 stud.
- 붙이기: Play에서 R15 마네킹(회색) UpperTorso에 WeldConstraint · 크기 = 어깨 폭(양 윗팔 바깥까지) × 몸통 높이 1.35 × 몸통 두께 1.45로 축별 맞춤. LOOK3 = 기존 검증 더미(`ArmorWearDummy` · 대검 · tier1|legendary) - 바닥층(누빔 옷)이 같이 입혀져 있다(생성 쪽은 맨 마네킹).

- **생성 시간**: 4개를 비동기로 동시에 걸어 약 1 ~ 1.5분 안에 모두 끝났다(도구가 개별 시간을 주지 않음 - 시작 ~ 마지막 완료 기준).
- 삼각형 상한은 거의 그대로 채운다(상한 = 실제). 2,000에서 이미 판 테두리 · 버클 · 보석이 다 나오고, 8,000은 곡면이 매끄러워질 뿐 장식이 늘지 않는다 → 이 크기에서 2,000 ~ 4,000이면 충분.

## 3. 등급색 재사용 가능한가 → 아니오(색이 구워짐)
- 텍스처 픽셀 표본(7픽셀마다): 2,000 = 주황 29% · 금 24% · 갈색 36% · 회색 6% · 기타 6% / 8,000 = 주황 38% · 금 15% · 갈색 30% · 기타 16%. **투명 0%**.
- MeshPart `Color`는 TextureID가 불투명이면 보이지 않는다 → 파트 색으로 등급을 바꿀 수 없다. LOOK3처럼 "색 지도 + 구역 틴트"가 아니라 색이 한 장에 섞여 있어, 등급색만 바꾸려면 ① 등급마다 다시 생성(모양이 바뀜) ② 텍스처의 주황 영역만 색상 이동(금 테 · 가죽 경계가 같이 번짐 · 런타임 EditableImage는 메모리 부담) 둘 다 비싸다.

## 4. 같은 설명 2회 생성 비교(4,000 · 4,000 2회차)
- 1회차: 세로 가죽 멜빵 2줄 + 가로 겹판 가슴 + 소용돌이 어깨판 + 버클 벨트.
- 2회차: 작은 방패형 가슴판 + 아래로 퍼지는 판 치마 + 둥근 어깨판, 멜빵 없음.
- 같은 것: 색 배치(주황 + 금 테 + 갈색 벨트) · 가슴 보석 자리. 다른 것: 실루엣 · 판 나눔 · 어깨 모양 전부. **같은 장비의 등급 사다리로 묶기 어렵다.**
- 보석 색도 흔들린다(호박을 요청했지만 2,000 = 빨강 · 8,000 = 보라빛).

## 5. 부수 사실
- 생성할 때마다 계정에 에셋이 자동 게시된다(publishedAssetId 4개: 96864892443688 · 122590351025785 · 132921385130887 · 94844449476235 - 메시 107839643389783 · 73200359263171 · 105963284619434 · 92919954098776). 삭제 금지 규칙대로 그대로 둠 · 게임 코드 · ArtAssetIds에는 연결 안 함.
- 생성 모델은 Edit 작업공간에 들어오고 Play로는 복사되지 않았다(Play에서는 `AssetService:CreateMeshPartAsync`로 메시 id에서 다시 만들어 붙임). 시험 뒤 Edit의 생성 모델 4개는 `ServerStorage.MeshGenTest_1004`로 옮겨 두었다(작업공간에 안 보이게 · 삭제 안 함 · 필요 없으면 사용자가 Studio에서 지워도 됨).
- Creator Store 모델 삽입은 쓰지 않았다.

## 6. 쓸 수 있는 곳(제안 - 결정은 사용자)
