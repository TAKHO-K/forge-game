## 가정 · 결정 로그

### 순서
1. [순서] B(장비 보기)를 A(순위 창)보다 먼저 커밋했다 - A3 "이름을 누르면 무기만 보기"가 B의 장비 보기 창(`Inspect.openCard`)을 쓴다. B를 되돌리면 A도 같이 영향받는 의존이라 B를 앞에 둔다.

### A 순위 창
2. [A1 입구] **HUD [순위] 버튼 = 칩 스택 왼쪽 [파티] 버튼 바로 아래**(`ScreenMap.TR.leaderboardToggle`, 폭 72 · 높이 36 / 모바일 44). 이유:
   - 메뉴바 4번째 칸: 폰 ScreenGui 높이 302에서 버튼 4칸 = 48 × 4 + 6 × 3 = 210. 세로 중앙(151)에 두면 아래 끝 256 > BL 예약 위 끝(302 × 0.55 = 166) → 90을 올려야 하는데 위로 올릴 수 있는 한도는 151 − 105 − 8 = 38(P2.5b 확인과 같은 결론).
   - 칩 스택 왼쪽 열은 [파티] 버튼 하나뿐이라 그 아래가 비어 있다. 폰에서 y 104 ~ 148 = BR 예약(y ≥ 151) 위 · 드랍 피드(칩 스택 아래) 위 · TC 토스트 줄(y 64 ~ 104) 아래. 요청 배너(폰에서 칩 스택을 덮을 수 있는 기존 규칙)가 뜨면 이 버튼도 잠깐 덮일 수 있다 - 기존 [파티] 버튼과 같은 조건.
   - 새 아이콘 · 에셋을 만들지 않는다(COMMON §1) → [파티] 버튼과 같은 글자 버튼 "순위". 왕관 아이콘은 에셋 단계(F5)에서.
   - 단축키는 넣지 않았다(새 단축키는 사용자 실제 키보드 확인이 필요 - COMMON §2). PC도 버튼으로 연다.
3. [A2 탭 배치] 왼쪽 세로 레일(전체 · 직업별 · 파티 · 시즌). 가로 탭(Tabs 킷)은 폰 창 본문 높이 약 221에서 탭 40 + 내 순위 줄 44 + 목록이면 목록이 2.5줄뿐 - 레일로 옆으로 빼고 "내 순위"는 목록 위 머리 줄(직업 칩 오른쪽)에 고정해 목록 약 3.8줄을 확보했다.
4. [A2 내 순위] 서버 board 응답에 "캐시(상위 100) 안의 내 줄"을 같이 싣는다(저장소 요청 0). 캐시 밖이면 클라가 "me" 요청 1회(서버 간격 10초 · 창 60초 캐시 · 간격에 걸리면 10.5초 뒤 한 번 더). 파티는 캐시만 본다(P3a 규칙).
5. [A2 이름] 정렬 저장소에는 키(UserId)와 숫자만 있다 → 서버가 순위표 갱신 때 모르는 id만 `UserService:GetUserInfosByUserIdsAsync`로 200명씩 한 번에 풀어 캐시(상한 5,000 - 넘으면 비움). 같은 서버 사람은 Players에서 바로. 못 풀면 화면은 `#<id>`. 요청 수: 새 id 200명당 1회 · 90초 갱신마다(첫 갱신 뒤로는 새로 순위에 든 사람만).
6. [A2 시즌 탭] 시즌 번호 · 기간 · 남은 기간(시작일 미정이면 "아직 정해지지 않았습니다") · 규칙 4줄. **지난 시즌 순위표는 넣지 않았다** - 지금 시즌 1이라 지난 시즌이 없고, 시즌 전환 방식이 P3a 결정 필요 1(미정)이다 → 결정 필요 1과 묶음.
7. [A2 전체 탭] "전체(최고 스테이지)" = 개인 순위표(personal - 클리어한 보스 스테이지 최고, 이번 시즌). 전 시즌 통합 순위는 저장소가 없다(P3a는 시즌별로만 나눴다).
8. [A3 카드] 줄을 누르면 카드 요청(무기만 - 서버 카드에 방어구가 없다) → 장비 보기 창을 카드 모드로 연다(방어구 칸 "?" · 펼치면 "리더보드에서는 무기 · 보석만 공개됩니다"). 두 창 모두 window라 장비 보기를 열면 순위 창이 닫힌다 → **장비 보기를 닫으면 순위 창이 다시 열린다**(다른 창을 열어 닫힌 경우는 제외 - 스택이 비었을 때만). 탭 · 직업 선택은 유지된다.
9. [A3 파티 줄] 파티 줄을 누르면 멤버 이름이 그 아래 펼쳐지고(같은 줄 다시 = 접힘), 멤버를 누르면 그 사람의 개인 카드(u<id>)를 연다. 파티 상세(partyDetail) 저장소는 읽지 않는다(멤버 id는 키에 있다 - 읽기 요청 0).
10. [A · Studio 확인] Studio 수동 Play는 순위표를 읽지 않는다(P3a 리뷰 10) → 화면 확인용 `/gg lb fake`(수동 Play에서만 - 캐시 · 이름 · 카드를 가짜로 채움, 저장소 요청 0, Play가 끝나면 사라짐). 요청한 사람은 개인 37위 · 자기 직업 12위 · 파티 5위, 다른 직업은 "100위 밖(스테이지 40)".

### B 장비 보기
11. [B1] 칸 목록(무기 · 갑옷 · 장갑 · 신발 · 보석 1 ~ 5) → 칸을 누르면 **바로 아래에 상세가 펼쳐진다**(아코디언 - 여러 칸을 같이 펼칠 수 있다, 같은 칸 다시 = 접힘). 옛 떠 있는 툴팁(ItemTooltip)은 이 창에서 뺐다(알림 속 아이템 툴팁은 그대로).
12. [B1 상세 줄] 무기 = 등급 · 강화 · 무기 배율(등급 배율 × 강화 누적 배율 - PlayerCombat.gradeMultiplier × Enhance.getTotalMultiplier) · 보석 n/5칸. 장비 = 등급 · 레벨 · 기본 효과(Inherit.baseStat = 가방 "착용 대비"와 같은 값) · 옵션 · 굴림 위치. 보석 = 등급 · 레벨 · 옵션 · 굴림 위치. "강화"는 무기에만 있다(방어구 · 보석은 강화가 없다).
13. [B2 비교] 차이 = **상대 − 나**(상대 장비가 나보다 좋으면 +, success 색 · 나쁘면 danger 색 · 같으면 회색). 옵션은 같은 옵션일 때만 차이를 낸다(다르면 글만 나란히). 옵션 값은 그 장비를 쥔 사람의 직업 기준(직업 특화 옵션은 직업이 다르면 0 - Option.valueOf 그대로). 칸 머리 오른쪽에 요약 차이(무기 = 무기 배율 % · 방어구 = 기본 효과 · 보석 = 같은 옵션 값).
14. [B2 내 장비] 비교를 켤 때 InspectPlayer(내 id)로 한 번 받는다(서버 간격 0.5초에 걸리면 0.6초 뒤 한 번 더). 서버 변경 0. 창을 열 때마다 새로 받는다(방금 바꿨을 수 있다).
15. [B3] 일반 이름 클릭(파티창 · 드랍 피드 · 태초 배너 → 이름 메뉴 [장비 보기])은 기존 서버 조회 그대로 전부 공개. 리더보드만 카드 모드.

### C 인벤토리
16. [C1 토글] "상세가 토글로 열림" = **같은 칸을 다시 누르면 상세가 닫힌다(선택 해제)**. 가방 칸 · 착용 칸(무기 포함) · 보석 홈(PC 클릭) · 보유 보석(PC 짧은 클릭 - 폰 탭은 원래 토글)에 넣었다. 기존 상세 바(PC) · 시트(폰)를 그대로 쓴다(새 떠 있는 창을 만들지 않았다 - 판매 · 분해 · 계승 · 확인창 · 연타 방지 규칙이 이미 이 바에 붙어 있어 옮기면 규칙이 두 벌이 된다).
    - PC 더블클릭(0.35초 안의 두 번째 클릭)은 기존대로 착용 · 해제 · 자동 장착이 먼저다(토글보다 앞).
17. [C1 표시] 굴림 위치(%) = EquipCompare.rollPercent(장비 보기와 같은 함수 · 옵션 게이지와 같은 식)를 메타 줄에 붙였다(치명 = 치확 / 치피 두 값). 장착 여부 = 이름 뒤 "(가방)" · "(착용 중)" · 보석 "장착 중" / "보유 보석(미장착)".
18. [C2] 판매 · 분해 버튼 · 확인창(영웅 이상) · 판매 즉시 선택 해제 · 연타 1개는 S21-0 규칙 그대로(코드 변경 0). **잠금 장비는 기존 규칙 그대로 판매 · 분해 버튼이 흐리게 막힌다**(지시의 "잠금은 확인창"을 "잠금 = 판매 불가(기존 유지)"로 읽었다 - 잠금을 확인창으로 넘겨 팔 수 있게 하는 것은 규칙 변경이라 결정 필요 2).
19. [C2 보석 판매] 보석에는 [판매]가 없다 - 서버에 보석 판매 경로 · 가격이 없다(분해 = 가루만). 새 가격은 밸런스 · 규칙 변경 → 결정 필요 3. 보석 상세에는 기존 [분해] · [재련] · [장착].
20. [C3] "착용 대비" 줄 · [계승]은 P2.5b 그대로(가방 장비 상세).

### D 스킬 툴팁
21. [D3 단일 소스] 서버에 `server/SkillStats.lua`를 새로 두고 **SkillServer의 공격력 · 1타 계수(옵션 · 틱 수) · 쿨다운 · 속사 배율 · 분신 지속과 HealCast의 치유 배수를 이 모듈 함수로 옮겼다**(동작 변경 0 - 식을 한 곳으로 모음). 툴팁 Remote(`SkillInfoRequest`)는 같은 함수로 수치를 만든다. 문구(규칙 · 사거리 · 틱)는 `shared/SkillTooltipText`가 SkillData에서 만든다(피해 재계산 없음 - 표시 형식만).
22. [D2 예상 피해] "1타 = 공격력 × 1타 계수"(치명 아님) · "치명 = × (직업 치명 피해 + 옵션)" · 채널형은 "대상 1명에 n타 합". 치명 기대값(확률 가중 평균)은 넣지 않았다 - 실제 한 번의 피해는 둘 중 하나라 대조 가능한 두 값을 보여 준다. 치유사 파티 버프(×1.25)는 파티에서만이라 예상 피해에 넣지 않고 "치유모드" 줄에 적었다.
23. [D2 치유모드 줄] 치유사가 아닌 스킬 = "치유사 파티 버프를 받으면 최종 피해 ×1.25(모드와 무관)" · 치유 = "치유모드면 회복 · 딜링모드 + 파티면 쉴드" · 딜링모드 = 지금 모드.
24. [D1 입력] 폰: 누른 채 0.4초 → 툴팁(칸 왼쪽 - 손가락이 누른 칸을 가리지 않게), 떼면 닫힘, 이 누름의 Activated는 삼킨다(시전 안 함). 0.4초 전에 떼면 기존대로 시전. 손가락이 칸 밖으로 미끄러져 떼도 화면 어디서든 뗀 순간 닫힌다. PC: 마우스 올림 = 툴팁(칸 위), 클릭 = 시전(기존). Studio `ForceTouchLayout`이면 마우스 왼쪽도 터치처럼(길게 누르기를 PC에서 실제 입력으로 확인).
25. [D1 대상 칸] Q · E만(잠긴 3칸 · 대시는 스킬이 아니다).
26. [D3 검증 경로] SkillServer의 요청 처리를 `handleSkill` 함수로 이름 붙이고 Studio에서만 `ServerStorage.SkillCastDebug`(BindableFunction)로 같은 함수를 부를 수 있게 했다(결과 이벤트를 모아 돌려준다) - 검증 (나)가 실제 시전 경로로 쏘고 툴팁 수치와 대조한다.

1. **지난 시즌 순위표**: 시즌 탭에 지난 시즌 결과를 보여 줄지(시즌 전환 방식 = P3a 결정 필요 1과 묶음). 지금은 시즌 정보 · 규칙만.
2. **잠금 장비 판매**: 지금 = 잠금이면 판매 · 분해 버튼이 막힌다(기존). "잠금은 확인창"을 "잠긴 것도 확인창을 거쳐 팔 수 있다"로 바꿀지 - 규칙 변경.

4. **리더보드 입구 아이콘**: 지금 글자 버튼 "순위". 왕관 아이콘은 새 에셋(F5 에셋 단계).
