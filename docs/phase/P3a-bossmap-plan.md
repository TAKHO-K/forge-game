# P3a 보스맵 계획 - 4인 원형 아레나 6종(구현) + 새 보스용 규칙

사용자 지시(P3a 도중): 보스전 맵을 지금보다 크고 웅장하게, 최대 4인 입장을 고려한 4인 전용 맵 6종, 앞으로 추가될 보스를 고려한 계획(기존 맵 재사용 또는 신규 맵의 크기). 카툰 그래픽(외곽선) 분위기, 보스와 어울리는 색감 · 지형지물, 끼임 · 맵 오류 없음.
구현 = `shared/data/BossArenaMapData.lua`(데이터) · `server/BossArenaMap.lua`(빌더) · `client/BossArenaMapView.client.lua`(파편). 검증 = P3a(가) · (나C).

## 3. 새 보스를 추가할 때 - 재사용 또는 신규

**판단 순서**

1. **기믹이 새 지형(킷)을 요구하지 않는다** → 기존 6종 중 속성이 같은 맵을 **재사용**(데이터 `maps[새 id] = maps[기존 id]`의 사본 + 색만 바꾸기). 속성이 없으면 기본 맵 "시련의 원형장"(`BossArenaMapData.default`)이 자동으로 쓰인다 - 테마가 없어도 보스전은 열린다.
2. **새 킷이 필요하다**(안전지대 · 발판 · 피뢰침 같은 고정 지형) → 킷은 `BossData`의 킷 함수로 쓰고 자리는 **아레나 반경에서 계산**한다(`ARENA_RADIUS` - 전갈 · 심해 킷이 선례). 맵 테마는 1과 같이 재사용 또는 신규.
3. **반경을 바꿔야 한다**(아래 크기 규칙에 안 맞을 때만) → 반경은 지금 슬롯 공통값이라 보스별로 다르게 하려면 `WorldConfig` 슬롯이 반경을 보스전마다 받아야 한다(기반을 슬롯마다 한 번 짓는 구조라 반경별 슬롯 묶음이 필요 - 설계 작업). 지금 6종은 전부 120.

**크기 규칙(4인 기준, 반경 R)**

| 조건 | 식 | 반경 120에서 |
|---|---|---|
| 가장자리 회피(C2) | `BossSim.checkDensityCircle` 48칸 × 깊이 1 · 3stud 실패 0 | 0/48 · 0/48 |
| 안전지대 도달(킷이 있는 보스) | 원 안 어디서든 가장 가까운 안전지대까지 ≤ 그 스킬의 `dodge.distanceStuds` | 범람 54.7 ≤ 57 |
| 파동 | 중심 파동이 벽까지: R ≤ 파동 최대 반경(140.6) | 120 ≤ 140.6 |
| 4인 분산 | 산개 원이 네 사람 모두를 한 번에 덮지 않게 원 중심 간 거리 ≥ 2 × 최대 원 반경을 네 명이 확보할 면적 - R ≥ 4 × (원 반경 × 1.152) × 2 ÷ π ≈ 20 | 넉넉함 |
| 걸음 | 보스 이동 속도 ≤ 10 · 플레이어 16 - 반대편 벽까지 2R ÷ 16 = 15초 | 15초(추격이 지루해지는 상한 - R 140이면 17.5초) |
| 성능 | 기반 26 + 장식 · 구조물 + 킷 ≤ 약 100파트 | 6종 실측 = 보고서 ④ |

**권장**: 새 보스도 반경 120을 기본으로 한다. 안전지대가 넓게 흩어져야 하는 기믹(범람처럼 "가장 가까운 X까지 달린다")은 R을 키우지 말고 **안전지대 개수를 늘린다**(심해 군주 4 → 8처럼) - 반경을 키우면 걷는 시간이 늘어 모든 패턴의 여유가 줄어든다. 반경 140 이상은 파동 최대 반경(140.6)을 넘어 "벽까지 닿는 파동"이 깨지므로 파동 반경도 같이 정해야 한다.

## 4. 에셋 교체(카툰 최종 외형) 때 할 일

- kind별 빌더(`DECOR.*` · `OBSTACLE_LOOK.*`)만 모델 복제로 바꾼다. 충돌 기둥(`ArenaObstacleCollider`)은 그대로 둔다 - **보이는 모양 ⊂ 충돌 기둥**이 유지되게(맞았을 때 크기가 줄지 않게 이미 바꿨다).
- 외곽선: 최종 에셋이 자체 외곽선(역 헐)을 가지면 `Highlight`를 끄고 한도(31)를 비워 둔다.
- 파편: `BossArenaMapView`의 조각 파트를 에셋 파편으로 바꾼다(판정 없음).

- 사운드 · 조명(Lighting) - 새 에셋 규칙과 함께.
