# C1 결정 5 보정 보고 - 막힘 방향 = 성장 (2026-09-27)

지시 = "[C1 보정 + D1] 파트 0". 검증 = COMMON §7-1(개정 - 이번 수정만). 저장 · 경제 수치 변경 없음. 판정 변경이라 리뷰어 1회.

## ① 바뀐 규칙

| 항목 | 전(C1 마무리) | 후 |
|---|---|---|
| 막힘 | 스틸 불가 + **스테이지가 더 높음** | 스틸 불가 + (**성장이 더 높음**(성장 차 자체가 스틸 불가 사유일 때) **또는 스테이지가 더 높음**) |
| 성장 비교 | - | `MobShare.compareGrowth` = 환생 횟수 → 같으면 레벨 |
| 같이 때리는 쪽(follower) | 스틸 불가 + 스테이지가 같거나 낮음 | 스틸 불가 + 성장도 스테이지도 높지 않음 - 주인 불변 · 기여 10% 채우면 보상(기존) |
| 막힘 면제 | 8초 안 참여자 전부(쫓김 포함) | 8초 안 **때리거나 도운** 참여자만(쫓기기만 한 사람은 새로 닿는 것과 같다) |

- 한 판정(`blocksAgainst`)을 서버 막힘 · 어그로(`MonsterState.canChase` → `isBlocked`) · 클라 자물쇠(`lockedFor`)가 같이 쓴다 → 강한 계정 화면에는 초보 몹이 잠겨 보이고, 몹도 그 계정을 쫓지 않는다.
- "같이 때리는 쪽 보상 없음" 안은 쓰지 않았다(지시대로).

**지시 문구와 다른 점 2가지(판단)**

1. **"스테이지가 더 높음"도 막힘에 남김**: 성장만 보면 "성장은 낮은데 스테이지가 높은 사람"(예: 환생 1 · 레벨 900 · 스테이지 300)이 환생 2 초보 몹에 follower로 끼어든다. follower도 참여자라 **기준 스테이지를 300으로 끌어올려** 주인 몹의 체력 · 주는 피해가 300 기준이 되고 어그로 필터가 주인을 놓게 된다(방해 · 즉사 경로). 그래서 follower = "성장도 스테이지도 높지 않은 사람"으로 좁혔다. (가) 검증 "n 반대 - 스테이지 300" 행.
2. **성장 차가 스틸 가능 범위 안이면 성장으로 가르지 않음(리뷰 2)**: 환생이 같고 레벨 차가 표 안(예: 31 vs 30)인데 스테이지 차 15로 스틸 불가인 경우, 레벨 1 차이로 막힘 방향이 뒤집히지 않게 옛 규칙(스테이지)으로 가른다. 지시의 목적 = "강한 계정" 차단.
