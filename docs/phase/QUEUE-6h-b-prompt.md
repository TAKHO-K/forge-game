# 알파 전 점검 6시간 대기열 (새 기능 없음 — 회귀·저장·보안·도구·정리·테스트 키트)

## 대기열 규칙 (가장 중요)
- 시작 시각(한국 시간) 기록. 시작 + 6시간이 지나면 새 항목 시작 금지 → 진행 중 항목 정리 → 커밋·푸시 → 상태 파일·보고서 갱신 → 멈춤. 사용량 한도 경고 때도 같게.
- 진행 상태 파일·보고서는 docs/phase 기존 파일명 규칙으로 새로 만든다(예: QUEUE-6h-b-state / QUEUE-6h-b-report). ★QUEUE-10h-report는 수정하지 않는다(사용자가 19시 이후 캡처 예정).
- 무인 진행: 큰 결정도 되돌리기 쉬운 쪽 + 스위치 + 결정 필요 기록. 저장 손실 위험만 건너뜀.
- 알림 규칙: 태초 = 같은 서버 + 본인 연출만, 전 서버 = 초월부터. §7-6: 공통 입구 재사용 + 이름 규칙 일관성.
- ★손대지 말 것(사용자 결정 대기 — 문제를 발견해도 "결정 대기 영향"으로 기록만):
  스킬 해금 시점(E·R·T 잠금 여부), 캐주얼 1,000 목표·경험치 곡선, 후반 골드 소모처(옵션 리롤·재련 비용), 환생 무료권 쓰임, 펫 해금 기준, 가방 칸 수, 영혼 인원 산정, 메인 퀘스트 해금 문구, 하드코딩 문자열 TextData 이동(번역), QUEUE-10h-report §10 결정 12개 전부, H1 마을·NPC 배치, NPC 외형, A2 카툰, 상품 가격·수익화, 사운드 음원, 순위 창 최종안, 클라 그래픽 성능 최적화.
- 수치·밸런스 값은 바꾸지 않는다(버그로 인한 명백한 오류만 예외, 이유 기록).

## R0 — 준비 (10분)
- git pull, 미커밋 변경 확인(있으면 건드리지 말고 기록 후 그 파일은 피함). STATE.md 요약만 읽기.
- 이 지시서 전문을 docs/phase에 저장(기존 규칙), 상태 파일 생성.

## R1 — 전체 회귀 (알파 전 마일스톤)
1. 모든 검증 블록(로컬 하네스 + Studio VerifyOnly 전 블록)을 실행하고 결과표 작성: 블록 / 통과·실패 / 분류.
2. 실패 분류와 처리:
   - 진짜 버그 → 수정(손대지 말 것 목록에 닿으면 기록만).
   - 설계 변경으로 기대값이 낡음 → 기대값 갱신(이유 한 줄, 어느 결정·커밋 때문인지).
   - 삭제된 기능을 읽는 블록(아슬아슬 회피·강탈·역전·파편·retired 종 등) → 블록 삭제 또는 새 기능 기준으로 교체.
   - 알려진 옛 블록 정리: 삭제 스킬 읽는 블록, M1-3T 저장 버전, M1-0 파동 개수, S01(나) 스폰 전제, S12b(나).
3. ★Play 1회: Studio 전 블록 한 번에(VerifyOnly 전체), 결과 로그 저장.

## R2 — 저장 안전 감사 (출시 사고 1순위)
1. 이관 체인 전수: 모든 SAVE_VERSION(가장 옛 버전 ~ 현재)마다 대표 저장 표본(fixture)을 만들고 현재 버전까지 이관 → 필드 보존 확인. migrate({}) = 새 계정 기본값 완전성(첫 5분 안내·출석·퀘스트·펫·설정 켜짐 상태) 확인.
2. 손상 입력: NaN·inf·nil·음수·타입 틀림·너무 큰 배열·모르는 필드 → 거부 또는 안전값, 저장 안 깨짐.
3. DataStore 흐름: UpdateAsync 사용, 재시도·백오프, 세션 잠금(두 서버 동시 접속 시 덮어쓰기 방지), BindToClose 저장, 저장 실패 시 사용자 데이터 보호(빈 데이터로 덮어쓰기 금지), 요청 예산.
4. 복사(dupe) 경로 점검: 자동 줍기(한 아이템 한 소유자 잠금), 분해·판매·계승·각성·잠금, 부화 연타, 보상 수령(출석·퀘스트·보스), 튕김 직전 수령 → 재접속. 각 경로에 하네스 1개.
5. 결과 → docs/design에 저장 감사 문서(기존 규칙). 치명은 바로 수정.
6. ★Play 1회(저장 변경이 있었다면): 옛 저장 → 새 버전 왕복, 새 계정 첫 접속.

## R3 — 보안·치트 감사
1. RemoteEvent·RemoteFunction 전수 목록: 이름 / 클라가 보내는 인자 / 서버 검증(타입·범위·소유권·거리·쿨) / 속도 제한 유무.
2. 클라가 정하면 안 되는 값: 피해량, 위치·이동 속도, 궁극기 게이지·쿨, 골드·재화, 드랍 결과, 퀘스트 완료, 부활, 영혼 상태 → 서버 판정인지 확인.
3. 공격 하네스: 각 원격 호출에 잘못된 인자·초당 100회 연타·남의 아이템 ID·먼 거리 요청을 넣어 거부 확인.
4. /gg 개발 명령이 퍼블리시 서버에서 막히는지(개발자 UserId·Studio 전용) 확인.
5. 결과 → docs/design에 보안 감사 문서. 치명은 바로 수정, 나머지 우선순위표.

## R4 — EconSim 난수 분리 (도구만, 게임 값 변경 없음)
- 시스템별 난수 흐름 분리(드랍 / 전투·치명 / 옵션 굴림 / 부화 등) 또는 안끼리 같은 시드 공통 난수. 목적 = 한 축만 바꾼 비교에서 ±3% 흔들림 제거.
- 재기준선: 현재 코드로 3프로필 다시 측정 → 이전 값과 흔들림 범위 안인지 확인. 같은 시드 두 번 = 완전히 같은 결과인지 확인.
- 안 비교 방법을 docs에 5줄로(앞으로의 경제 결정 기준).
