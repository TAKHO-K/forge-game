# 검증 블록 실행 순서 · 격리 규칙 (QUEUE-ALL6 B5 · 2026-10-01)

> 러너 = `roblox/src/server/DevTools.server.lua`(29-1 체인 · `deferHeavyPure`) · 스위치 = `ReplicatedStorage` Attribute `VerifyOnly`(COMMON §3).

## 1. 무엇이 문제였나 (근거)
- QUEUE-STUDIO V2: `BR1(나)` 1회차 **60/66**(대공 잡기 6건 X) → 같은 코드로 **단독 실행 66/66**.
- 1회차에는 `P0(가)`(EconSim 기준선 전체 - 약 2분 연산)가 **서버 시작 때 `task.spawn`**으로 돌았고, 같은 시간에 `BR1(나)`가 대공 잡기 체공 시간(실시간 Heartbeat · 초 단위 대기)을 쟀다.
- 두 실행 사이에 바뀐 것 = 같은 Play에 묶인 블록 목록뿐(제품 코드 · 데이터 무변경 · 같은 커밋). X 6건은 모두 "체공 · 던짐 시각"처럼 서버 틱 지연에 민감한 항목이었다 → **검증끼리의 간섭이지 제품 버그가 아니다.**

## 2. 규칙
1. **무거운 (가)** = 큰 표본 · 긴 연산 블록. 서버 시작 때 바로 돌리지 않고 `deferHeavyPure`로 **29-1 체인 끝**(모든 (나)가 끝난 뒤)에서 차례로 돈다.
   - 목록: `S03(가)` · `S14(가)` · `P3c(가)` · `G1-0(가)` · **`P0(가)`(QUEUE-ALL6에서 옮김)** · 체인 안 `P3a(가C2)` · `P3d(가E)` · `P3dF(가E)`(체인 맨 끝 칸).
   - 새 무거운 (가)를 만들면 같은 방식으로 등록한다(`task.spawn` 금지).
2. **실시간 (나)** = 초 단위 대기 · 체공 · 시전 시간 · Heartbeat 틱을 재는 블록(`BR1(나)` · `BR1-2(나)` · `BR1-4*(나)` · `29-1` 실시간 · `ALL6(나)` 등). 무거운 (가)와 **시간이 겹치면 안 된다** - 규칙 1로 순서가 보장된다.
3. 그래도 한 Play에 `BR1(나)` + 무거운 블록 여러 개를 묶는 것보다 **`VerifyOnly`로 `BR1(나)`를 따로** 도는 것을 기본으로 한다(대공 잡기 66항목은 단독 약 3분).
4. X가 나오면 먼저 **단독 재실행**으로 간섭인지 가른다(같은 커밋 · 같은 블록 단독 = O이면 간섭). 간섭이면 이 문서 규칙 1에 그 블록을 넣는다(값을 만져 통과시키지 않는다 - COMMON §0).

## 3. 확인
- 콘솔 `[DevTools] 무거운 (가) N블록을 체인 끝에서 시작(QUEUE-B1 결정 4)` 줄의 N에 `P0(가)`가 포함되는지(QUEUE-ALL6 I 회귀에서 `BR1(나)` + `P0(가)` 한 Play = 66/66 기대).
