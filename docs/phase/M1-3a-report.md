# M1-3a 보고 - 보스 입장 규칙 "관문 등록"(M1-3 본편 전 · 2026-09-26)

지시 = "[추가 - 보스 입장 규칙 관문 등록]" + 보완 두 번(한눈에 관문 · 색 · 크기 · 상호작용 첫 등록 / 등록 전·뒤 빛기둥 · 문양 · F · 첫 등록 연출). M1-3 본편(대형 지형 · 물 · 신전 · 둥지)은 다음 세션에서 새로 시작한다(사용자). **저장 v40**.

## ① 규칙

| 항목 | 구현 |
|---|---|
| 등록 | 관문 앞 상호작용(ProximityPrompt - **F 짧게** · 폰 = 상호작용 버튼 · 관문 중심에서 허브 쪽 30 = 발판 밖) 또는 보스 스테이지에서 발판을 밟아 입장(관문 방문). 계정 저장 `world.bossGates`(v40) · 개발 도구 스냅샷(`world` 통째) |
| 원격 입장 | 등록된 보스는 스테이지 선택 창 [원격 입장] = 옛 즉시 입장 경로(파티 검사 · 투표 그대로) · 복귀 = 각자 서 있던 자리. 토벌(BR2)은 같은 기록을 쓴다(지금은 토벌 입장 경로 없음) |
| 파티 | 멤버 중 한 명이라도 등록 → 전원 원격 입장(리더가 연다 - 기존 규칙). 따라간 사람은 등록되지 않는다(등록 = 본인 상호작용 · 본인 발판뿐) |
| 등록 전 | 보스 스테이지 = 관문까지 바닥 길 안내 + 오른쪽 위 "다음 목표: ○○ 관문을 찾아라 · 361m"(보스 색 · 지역명 왼쪽) · [원격 입장] 잠금 + [관문 안내] + 상태 줄 "🔒 원격 입장 - 관문을 한 번 찾아가면 열립니다". 등록하면 길 안내 · 추적이 꺼진다 |
| 신규 보스 | 관문 위치 · 색 = `BossData` 보스마다 `gate = { zone = "tier1", color = {…} }` 한 칸(구역 없는 작은 보스 섬 = `at = { angleDeg, r }`). 짓기 · 등록 · 원격 입장 · 길 안내가 이 목록(`WorldMapLayout.bossGates`)만 읽는다 |
| 튜토리얼 | 첫 보스(T1 구간 수호자 · 스테이지 5)는 지금 추적 · 길 안내만 - "등록 → 원격 입장" 가르치기 = P4-1 기록(`roadmap-v2.md`) |

## ② 관문 모습(한눈에 관문)

- 보스 색 큰 아치: 폭 40 · 높이 44(사람 약 5) · 기둥 8 · 들보 7 · 안쪽 네온 띠 · 빛 막 · 보스 색 발판. 색 = 수호자 보라 · 수정 하늘 · 심해 파랑 · 전갈 호박 · 폭풍 노랑 · 서리 얼음 흰파랑.
- **등록 전**: 빛기둥 흐리게 깜빡(투명 0.72 ~ 0.9 · 1.6초) · 들보 문양(마름모 + 가로 띠) 꺼짐(회색 무광) · 가까이(70) 오면 "관문 등록 [F]" 큰 안내(보스 색 테두리 - 폰 "관문 등록 - 버튼을 눌러요").
- **등록 뒤**: 빛기둥 밝게 꾸준히(0.2) · 문양 켜짐(보스 색 네온) - 사람마다 다르므로 클라가 칠한다(`client/BossGateMarks`). 토벌 관문도 같은 표지를 쓴다(BR2).
- **첫 등록 순간**: 문양 흰 섬광 · 1.6배 → 보스 색(1.2초) + 빛기둥 번쩍 + 화면 알림 "○○ 관문 등록! 이제 어디서든 입장할 수 있어요."(TC 중요 알림 4초).

## ④ 알려진 것 · 기록

- 파티 "등록 1명 + 미등록 3명"은 리더가 등록한 경우를 실제 서버로 쟀다(더미 3). **리더 미등록 + 다른 사람 등록**은 순수 규칙(`BossGate.usableFromFlags`)만 쟀다 - 다중 클라는 MCP 불가(사용자 실기).
- 검증 도구: Studio 전용 `ServerStorage.StageMoveHook`(BindableEvent) = 클라 스테이지 이동 요청과 같은 핸들러(라이브에는 없다).
- 고친 옛 버그: 보스 띠 [여기로 안내] 버튼의 `Visible` · `ZIndex`를 버튼 표(refs)에 써서 실제 버튼에 안 먹던 것 → `.root`.
- 관문 좌표 주의: `flatYaw`의 −Z = 바깥(관문 너머) · 허브 쪽 면 = +Z(첫 배치에서 문양 · 프롬프트를 바깥에 놓아 F가 안 닿았다).
