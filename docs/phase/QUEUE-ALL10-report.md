## 3. EconSim 정밀 결과(실제 EconSim 전체 · 스위치 켬 · 프로필 4종)

### 3-0 P1 근사 모형과 달랐던 점 · 조정
- 실제 EconSim에 P1 추천값을 그대로 넣으면 **선순환 폭주**가 났다: 상위 1% 8,410 → 22,500을 약 35시간에 통과한 뒤 22,500 이후 전역 재조정(0.12) 벽에서 수천 시간 정체.
- 원인: 이 게임은 스테이지 ≈ 캐릭터 레벨이고 처치 시간 목표가 일정해 **진행 속도가 "몹 HP 대비 힘" 배수에 그대로 비례**한다. P1 돌파 꼴 1.02^(−0.583x)는 1,500 동안 앞선 몫이 1.02^875배로 쌓이고, 초월 성장 배수(×3.5)도 그대로 영구 속도가 된다. P1 모형은 "기준선 시간에 맞춰 스테이지만 옮겨" 이 되먹임이 없었다. 돌파 계수를 1.05로 줄여도 상위 1% 3.5배 · 뒤 9.7배.
- 조정(허용 범위 = 돌파 계수 · 증가율 · 비용 계수):
  - **돌파 계수 = 기준 빌드 배수 × (1,500 구간만 1/2.4)**. 기준 빌드 = 중앙값 계승자의 무기 ×1.25 × 고급 수련 상한 × 초월 강화 기대치(계승 → 25,300 사이 일정하게 +0 → +20). D11 "몹 스탯 = 기준 빌드 표 + 돌파 계수"를 그대로 구현한 꼴 - 기준 빌드인 사람은 구간 안 2.4배 · 뒤 정상 · 빨리 산 사람은 그만큼 빠르다(D10).
  - 전역 재조정 κ 0.12 → **0.005**(25,300에서 ×2.51) · 초월 강화 단계 비용 28만 → **36만 마리분** · 나머지 제안값 그대로(돌파 2.4 · 고급 수련 1,840 × 1.03^n · 51 ~ 60 × 0.4 · 방어 수련 · 보석 0.2%).
  - 격자 원자료 · 실행 · 판정 스크립트 = `docs/phase/all10/econ/`(a10run.py · a10an.py · a10off.py · a10mult.luau).
