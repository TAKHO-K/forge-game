## 0. 경제 모형 5% 원인 (시뮬만 · 게임 코드 변경 0)

**결론: 남은 5%는 "모으는 동안의 인플레이션"이다. 모형 오류가 아니다(EconSim 수정 없음).**
- 지금 곡선 A(1.001^s)에서는 큰 구매(초월 강화 시도 = 사냥 9 ~ 66시간분)를 위해 골드를 모으는 사이 계정 최고 스테이지가 오르고, 가격(GoldCost = 계정 최고 기준)이 1.001^Δ만큼 같이 오른다. 모은 골드의 구매력이 깎인다.
- 완만한 곡선 C(1,000 뒤 √)에서는 Δ 동안 가격이 거의 안 오른다 → 이 손해가 사라져 빨라진다.
- GOLD-CURVE-1이 되돌린 것은 "사냥 스테이지 < 계정 최고"(약 60칸) 할증뿐이었다. 이 둘이 서로 다른 효과이고 크기가 비슷하다(각 약 −4 ~ −5%).

**계측(상위 1% · 25,300 도달 h · 실제 EconSim + 하네스 메모리 안 덮기 · `PROG-2B-1/sim/ref0_top.txt`)**

| 시나리오 | 바꾼 것 | 25,300 | A 대비 |
|---|---|---|---|
| A | 지금 곡선 | 2,154.5 | 0 |
| A + 비용 = 사냥 스테이지 | 할증만 없앰 | 2,063.0 | −4.25% |
| A + 보유 골드 구매력 유지 | 모으는 동안 인플레이션만 없앰 | 2,047.3 | −4.98% |
| A + 둘 다 | | 1,952.8 | −9.36% |
| C | 곡선만 | 1,973.8 | −8.39% |
| C + 둘 다 없앰(대조) | | 1,958.9 | −9.08% |
| C + 할증 고정 50칸 되돌림(GOLD-CURVE-1 Cg) | | 2,046.1 | −5.03% |
| C + 할증 정확히 되돌림(실제 사냥 간격) | | 2,052.2 | −4.75% |
| C + 인플레이션만 되돌림 | | 2,081.4 | −3.39% |
| **C + 둘 다 되돌림** | | **2,163.7** | **+0.43%** |

- 두 효과를 정확히 되돌리면 C가 A에 0.4% 안으로 돌아온다 → 원인 확정. 사냥 간격은 실측 평균 약 61칸(1,001 ~ 25,300 시간 가중)이고, 고정 50칸 대신 실측 간격을 써도 차이는 0.3%p뿐이다(간격 크기는 원인 아님).
- 인플레이션 몫은 20,000 도달 시점까지 거의 0(721.6 → 719.6h)이고 대부분 초월 강화 구간(20,000 ~ 25,300)에 있다. 큰 단위 저축이 그 구간에 몰리기 때문이다.
- 방법: `docs/phase/PROG-2A/sim/p2lib.lua`에 손잡이 3개를 더했다(옛 시나리오 결과 불변 - 켜야만 동작).
  - `costAtHunt` = 비용 기준을 계정 최고 → 직전 청크 사냥 스테이지로
  - `gapExact` = 새 곡선에서 할증을 1.001^(최고 − 사냥)으로 정확히 되돌림
  - `savings = "keep" | "A"` = 청크마다 최고 스테이지가 r0 → r1이면 보유 골드 × M(r1)/M(r0)(구매력 유지) · "A"는 지금 곡선만큼 깎음
  - 근사: 보정은 청크(레벨 1개) 끝 보유 골드에 한 번 건다(청크 안 점검 구매 사이의 변화는 무시).

**2절 초월 강화 비용 × 1.16 다시 판단**
- 두 효과 모두 실제 게임에서도 일어나는 경제 효과다(모형 오류 아님) → 곡선을 C로 바꾸면 실제 상위 1%도 그만큼 빨라진다. 맞춤이 필요하다.
- 인플레이션 몫이 초월 강화 구간에 몰려 있으므로 **초월 강화 levelKills × 1.16을 그대로 쓴다**(손잡이 하나 · GOLD-CURVE-1 G3과 같음). 최종 값은 7번 합친 고정점에서 다시 맞춘다(수련 · 치명 · 몹 기준 함수가 겹치므로).
